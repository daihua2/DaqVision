# AIIntegration 骨架与算法模块的分界

- 编写日期：2026-09-10
- 状态：**方案论定中**，未落码
- 依据裁定：**「把基础架构搭好，AI 集成侧只需扩展 Python 算法模块」**（2026-09-10 用户）
  ＋「一个服务装四个域，可扩展」＋「四个域整体重构」＋「前端做进 AICloud」

---

## 0. 这份文档要回答的唯一问题

**新增一个 AI 能力域，到底要写多少东西？**

目标答案：**一个 Python 文件**。除此之外一行不改、一处不配。

达不到这个答案的设计，就不满足"只需扩展算法模块"。下面每一条分界都是为这个答案服务的。

---

## 1. 分界原则：模块只懂算法

> **算法模块不知道 historystore 存在，不知道 VQT 是什么，不知道有证书、有 HTTP、有前端。**

它只做一件事：**给它数据，它给结论**；以及（可选）**给它带标注的数据，它给一个模型工件**。

反过来说，只要一件事**不是"算法怎么算"**，它就归骨架。这条判据用来裁决所有边界争议。

---

## 2. 骨架包办的八件事

| # | 骨架负责 | 为什么不能丢给模块 |
| --- | --- | --- |
| 1 | **身份与连接**：guid 首启生成 + 冗余落盘 + 永不重生成；mTLS 写连接（cert guid）、明文回环读连接（全量）；断线重连与退避 | 全服务共一份身份。让模块碰它 = 每个模块一套身份，与"一个服务一份 guid"直接冲突 |
| 2 | **取数**：按绑定订阅/查询点值，成帧、成窗、对齐、缺口处理 | 取数节拍、背压、跨域并发是宿主的事；模块各写一遍必然各写各的错 |
| 3 | **结论回流**：结论点的声明（`PushEntityConfigs`）与写入（`PostVQT`） | 见 §4：VQT 三元组的完整性**必须**由骨架在类型层强制 |
| 4 | **点位与命名**：结论点的 localId 分配、命名模板、点表组织、与被诊断设备的关联 | id 空间是二维的（方向 × 连接类型），模块碰它一定错 |
| 5 | **工作台状态**：标注、训练集、模型工件、训练任务的存储与生命周期 | 这是平台级资产，要能备份、能追溯、能授权；模块各存各的就是第二个 `mock_db.json` |
| 6 | **调度**：推理节拍、训练任务排队、并发与资源、失败退避 | 单进程多域共享算力，只能由宿主统一编排 |
| 7 | **对外接口**：那**一个** HTTP 口，含域发现与能力自描述 | 见 §5：前端要按能力渲染，不能按域名 `if/else` |
| 8 | **可观测**：日志、自指标、健康、降级态 | 降级态要周期性输出（连不上实时库这类决定可用性的事，每个重试周期都要报） |

## 3. 算法模块要写的（全部）

一个模块 = 一个 Python 文件，实现一个类。**除下列成员外，不需要知道任何别的东西。**

```python
class Domain:
    key = "vibration_lowfreq"          # 域标识，运行期值，不进骨架的任何枚举
    display = "低频振动诊断"
    version = "1.0.0"

    # ── 1. 声明：我要什么输入、我产出什么结论 ────────────────────────────
    def declare(self) -> Declaration:
        """骨架据此：向平台声明结论点、建立输入绑定、渲染前端。
        模块在这里只描述【语义】：要几路什么量、出哪些结论、结论的值域与单位。
        不写 localId、不写 globalId、不写任何 id —— 那是骨架的事。
        """

    # ── 2. 推理：给数据，出结论 ──────────────────────────────────────────
    def infer(self, frame: Frame) -> list[Finding]:
        """frame 里是已经取好、对齐好、带质量码与真实时刻的数据。
        返回结论。骨架负责把它变成 VQT 写回实时库。
        """

    # ── 3. 训练（可选，不实现即表示本域不支持训练）────────────────────────
    def train(self, dataset: Dataset, report: ProgressSink) -> Artifact:
        """dataset 是骨架按标注组装好的。返回模型工件，骨架负责存储与版本。"""

    # ── 4. 能力自描述（可选，缺省由骨架按实现了哪些方法推断）───────────────
    def capabilities(self) -> set[str]:
        ...
```

**新增一个域的完整清单：**

1. 写这一个文件；
2. 放进模块目录。

**没有第 3 步。** 不改骨架、不改路由、不改前端、不改配置、不动 proto。

## 4. ★一条硬约束：VQT 三元组由骨架在类型层强制

我方铁律：**所有实时数据一律完整 VQT 流转，V/Q/T 缺一不可**；
`T` 是**真实采样时刻**不是轮询时刻，`Q` 是**真实质量**不是默认 0。

⇒ 落到本设计：`Finding` 这个类型**不允许只填 value**。构造一个结论必须同时给出：

- **V**：值；
- **Q**：这个结论的质量 —— 输入有坏值、样本不足、模型未加载、置信度低于阈值，
  都必须落成质量码而不是悄悄给一个数；
- **T**：这个结论**对应的数据时刻**（帧的时刻），**不是算完的时刻**。

**"只填 V"在代码层不可能**：没有默认参数、没有可选字段。
这样即便模块作者不懂 VQT，也写不出违反铁律的结论。

> 这一条是从 v4 的教训来的：那边 `NaN/Inf` 被静默写成 `0.0`，坏值伪装成合法值。
> 把它挡在类型层，比写进文档让人记得住。

---

## 5. 域发现与能力自描述（前端零改动的关键）

骨架开的那个 HTTP 口上：

- `GET /api/ai/domains` —— 有哪些域、各自的 `display` / `version` / **能力位**；
- `GET|POST /api/ai/{domain}/…` —— 业务端点，`{domain}` 是运行期值。

AICloud 前端**按能力位渲染**：有 `train` 就出训练页，有 `annotate` 就出标注页，
没有就不出。⇒ **新增一个域，前端不改一行代码就能用**。

反例（不采用）：把四个域写死进前端路由或后端枚举 —— 那样每加一个域两侧各改一次，
"只需扩展算法模块"当场不成立。

| 2 | 结论点挂在**被诊断设备**下还是 AI 服务下 | 已问 AICloud，等**判据** |

| 5 | 算力放置（视觉将来下沉边缘？） | 单服务形态已定 ⇒ 下沉时整体搬，不影响本文分界 |

★第 4、5 两条**特意设计成不阻塞**：它们只改某个域的实现或部署位置，
不改骨架与模块的分界 —— 这正是这份分界该有的性质。
