## 0 设计前提

**不以现有运行环境为设计依据**（2026-09-17 用户定）。设计与硬件无关：
- 视频分析进程与骨架分离，**可部署在任意机器上**，有无 GPU/NPU 均可；
- 能带多少路、每路多少帧，**由部署时按该机器算力给定**，不写死在设计里。

## 2 数据流转

```
摄像头 ──RTSP──┬──▶ 录像 ──▶ 实时库（视频段）──▶ 前端回放 / 事后复核
               │
               └──▶ AI 服务：每路流一个取帧器（解码一次）
                        │  按挂在这路流上各算法要的最高帧率抽帧
                        ▼
                    检测层（共享模型：人、安全帽、车辆……）── 每帧每模型只跑一次
                        │
                        ▼
                    目标跟踪（每路流一份，给目标编号、记停留时长）
                        │
             ┌──────────┼──────────┬──────────┐
             ▼          ▼          ▼          ▼
           跌倒判定   越界判定   区域停留   未戴安全帽 ……（规则层，每个算法一个）
             │
             ▼
         告警事件 ──▶ 实时库（事件点 + 证据截图）──▶ 前端按事件时刻跳到回放
```

### 2.1 ★实时分析直接拉 RTSP，不从实时库取

实时库里存的是**编码后的视频段**，按段落盘：
- 从库里取要再解码一遍；
- 要等一段写完才能取到，**告警会晚一个段长**。

⇒ **实时分析由 AI 服务直接拉 RTSP**；实时库里的视频用于**回放和事后复核**。

### 2.2 ★一路流只解码一次，多个算法共享

几十种功能挂在同一路流上时，每个算法各自拉流解码，CPU 立刻耗尽。
⇒ **每路流一个取帧器**，解码后的帧分发给这路流上的所有算法。

### 2.3 ★检测层共享，规则层各算一份

跌倒、越界、区域入侵、区域停留，底层都是**先检测出人**，差别只在后面的判定规则。
⇒ 分两层：
- **检测层**：人、安全帽、车辆等检测模型。**同一帧、同一个模型只跑一次**，结果给所有要用它的算法；
- **规则层**：越界线、禁入区域、停留时长、跌倒姿态判定等，每个算法一份，计算量小。

加一种新功能，多数情况下**只加规则，不加模型**——这是能扩到几十种的关键。

### 2.4 目标跟踪要跨帧状态

越界要知道目标从哪边来、停留要计时、跌倒要看连续几帧的姿态变化。
⇒ 每路流一份跟踪状态（目标编号、轨迹、停留时长）。这依赖骨架「跨帧状态」那一格（待办 24）。

### 2.5 输出是告警事件，不是逐帧结论

每秒几帧都写结论点会冲垮实时库。
⇒ 只在**事件发生、结束**时写：事件类型、目标编号、开始/结束时刻、置信度，外加一张**证据截图**。
前端拿事件时刻去回放视频。

## 3 算法调度

| 规则 | 说明 |
| --- | --- |
| 帧率由算法声明 | 例：跌倒 5 帧/秒、越界 2 帧/秒、安全帽 1 帧/秒。取帧器按这路流上的**最大值**抽帧，分发时按各算法要的帧率降采样 |
| 检测模型按帧成批 | 同一时刻多路流的帧，送同一个检测模型时拼成一批推理 |
| 常驻 | 视频是持续任务，检测模型常驻，不做按需加载 |
| 预算 | 部署时给出「最多几路 × 每路最高几帧/秒」。配置超出预算时**拒绝保存并说明**，不偷偷降质 |
| 过载 | 运行中算不过来时**降帧率**、不断流，并在 `/health` 与日志里报出，不静默 |
| 进程 | 解码与推理放独立的重型进程；按 H-244，该进程可只读直连实时库，写结果仍由骨架 |

## 4 配置（与诊断五步一致）

1. 选视频流（AICloud 的视频监控流实体）
2. 加算法：跌倒监测 / 越界监测 / 区域入侵 / 安全帽检测 ……
3. 填参数：**在画面上画**越界线、禁入区域；灵敏度、停留时长阈值等
4. 保存即启用
5. 需要训练的算法再采样本（多数规则类不需要）
