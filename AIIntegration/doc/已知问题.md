## 1. ~~离散点（字符串/时刻型）用 `kRawData` 查历史**恒回空**~~ —— ✅ 已修复（hs 1.9.437）

- 发现：2026-09-10（AIIntegration 闭环自检）
- 根因定位：2026-09-10（同日，隔离实例四组对照）
- 归属：**historystore**（与本工程同一责任人，另一个仓）。**不是 AIIntegration 的问题。**
- 状态：**已修复并发布 —— historystore 1.9.437**（2026-09-10 当日）
  - 修法：把 `Raw` 抽成数值路径与离散路径**共用**的 `RawWindow()`，两条路调同一段（不复制实现）
  - 回归：新增「离散点 × 方法族」矩阵用例；变异验证撤掉修复后 5 个用例里 4 个变红
  - 验证：隔离实例 A 组 0→1 笔、C 组 0→4 笔；本工程闭环自检回读到 `String=正常 Q=1`
  - 投放：`ProtocolGate/thirdparty/historystore/{amd64,arm64}`，投放说明 `H-232`
  - 记录：`historystore/docs/2026-09-10-离散点Raw查询恒回空-根因与修复.md`

> ⚠️ **本条的第一版描述是错的，已订正。**
> 原写「字符串点写入后、**块提交前**查不到」——把它归因到落盘时机。
> 后续对照实验证明**与落盘无关**（见下 C 组）。错误的归因比没有归因更坏：
> 它会把人引到"等一等就好了"，而实际上等多久都不会好。

### 根因

`aggregator.cpp` 的 `AggregateDiscretePicks()` 准入判断：

```cpp
const bool isPick     = FirstValue|LastValue|FirstTime|LastTime|BeginInterpolated|EndInterpolated|Trend;
const bool isCountable= Count|ChangeCount|TimeGood;
const bool gridNotApplicable = IsGridFamily(method) && !isPick && !isCountable;
if (samples.empty() || (!isPick && !isCountable && !gridNotApplicable))
    return out;   // 注释写的是「非栅格族又没定义(MinTime/MaxTime)」
```

`Method::Raw`：`isPick=false`、`isCountable=false`，而 `IsGridFamily(Raw)` **恒为 false**
（该函数把 Raw 显式排除在栅格族之外）⇒ `gridNotApplicable=false` ⇒ **直接 `return out`（空）**。

⇒ **作者在那句注释里枚举了 MinTime/MaxTime，漏了 Raw。**

而离散点**什么时候会走到这条分支**，由 `engine_host.cpp::QueryMerged` 决定：

```cpp
if (LatestTypedValue(tagId, lvt, lat))
    discreteTag = (lvt == VType::String || lvt == VType::Date);
```

判据取**实时缓存里最后一笔带类型的样本**。所以：
**缓存里有带类型样本 ⇒ 走离散分支 ⇒ Raw 回空；缓存空（刚重启）⇒ 按数值走快路 ⇒ Raw 正常返回。**

### 决定性对照（隔离实例，同一个点 localId=1000）

| # | 条件 | `kRawData` | 说明 |
| --- | --- | --- | --- |
| A | 写一笔字符串，缓存里有带类型样本 | **0 笔** | 走离散分支 |
| B | 优雅重启（缓存清空，数据已在盘上） | **2 笔** ✅ | 按数值走快路 |
| C | 重启后**再写一笔**（缓存又有类型） | **又变 0 笔** | ★**决定性**：盘上那笔一直在 |
| D | 同一时刻改用 `kLastValue`（属 isPick） | **1 笔 `'第一笔'`** ✅ | 数据确实在，是 Raw 这条路被漏了 |

C 组排除了"提交/落盘"这个解释：数据一直在盘上，只因缓存里重新有了带类型样本就又查不到。

### 为什么这条要紧

**"查不到"与"没算出来"在调用方看来一模一样。** 分类型结论（「故障类型」这类）刚产生时去查
拿到空，按我方自己的纪律，空的含义应当是"这段没数据"。这正是一路在防的那类静默混淆 ——
而且它**不会自愈**：只要点还活着（缓存里有它的带类型样本），Raw 就一直查不到。

### 修法（已实施：取甲）

| | 改哪 | 说明 |
| --- | --- | --- |
| 甲 | `AggregateDiscretePicks` 接住 `Method::Raw`，把窗口内样本原样吐回 | 语义最正：离散点的 Raw 就该是"原始样本原样给" |
| 乙 | `QueryMerged` 里把 `Method::Raw` 排除出离散分支，让它走数值快路 | 改动最小（B 组证明那条路对字符串是对的） |

**取甲**，且比原提议更进一步：不在离散路径里"再实现一遍 Raw"，而是**把 Raw 抽成两条路
共用的一段代码**。理由 —— 本缺陷的成因就是"同一个方法在两条路各写一遍、其中一条忘了"；
再复制一遍只是把下一次漂移推迟。抽成一处之后，两条路**漂不了**。

★**回归缺口已补**：此前 hs 侧没有任何"离散点 × Raw"的用例（所以才漏得掉）。
新用例按**值类型 × 方法族**做成矩阵，不是只补 Raw 那一格 —— 只补一格，
下一个被漏掉的方法照样是静默的空。
