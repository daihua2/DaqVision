## 0 一句话

**现在满足不了。** 方案要三套 AI 模型（压机 / 伺服 / 电机振动）+ 一套 SPC 引擎，**没有一项能在现场出结论**。
卡在三层，按先后：

1. **现场数据**（不在我方手里）：三个真实设备组没有一条好值，压机四点从未产出过非零数据（F8）；
2. **方案与点表本身**：有几项这套传感器 / 采集链路兑现不了（§3）；
3. **我方实现**：压机域是作废设计、伺服域要的输入与方案对不上、四分类与 SPC 都没有（§2）。

第 1 层不解开，第 3 层写完也没数据可算。

## 1 方案要什么（摘）

| 模型 | 对象 | 判什么 | 输入点 | 周期 |
| --- | --- | --- | --- | --- |
| 压机 AI 预测模型 | 压装电缸 | 卡滞 / 压装不到位 / 配合间隙异常；三层：包络比对 → 形态特征 → SVM/RF + CNN-LSTM；另压装参数 SPC、电缸退化（空载回程扭矩、定位重复性） | `pm01_ad` / `af`（实时位移 / 力）、`fd` / `ff`（最终位移 / 力） | 100 ms；`fd`/`ff` 每件 |

| 电机 AI 预测模型 | 三轴振动测点 | 不平衡 / 不对中 / 轴承故障 / 机械松动四分类 | `v1_temp` + X/Y/Z 各 `acc` / `f` / `s` / `v` | 1 s |
| SPC 引擎 | 压装参数、拧紧轴电流、试验工位电流 / 电阻 | X̄-R、8 条 Western Electric 判异、Cpk | —（19 点表里**没有**这些点） | |

| 方案要求 | 我方现状 | 差距 |

| **电机振动模型** | [vibration_iso.py](../domains/vibration_iso.py)（GB/T 6075 烈度判级 + 方向性提示）与 [vibration_baseline.py](../domains/vibration_baseline.py)（相对基线偏离）吃三轴速度 + 温度 —— **离方案最近** | **四分类没有**：baseline 定案「故障分类先不做」；iso 的方向性（不平衡 / 不对中）实测单测点 0.767，只作提示不作结论 |
| **SPC 引擎** | 仓里**无**（grep `SPC` / `Western` / 包络 为空） | 归属未定（§6 U1） |
| **试验工位** | 无 | 点表里无点，不排 |

## 3 方案里这套硬件 / 链路兑现不了的（建议改方案文本）

| # | 方案写的 | 为什么兑现不了 | 依据 |
| --- | --- | --- | --- |
| 1 | 电机模型判「轴承故障」 | 传感器只出厂家算好的特征值、**不出原始波形**；只用速度有效值 + 基线偏离，在 SCA 10 个真实轴承故障上**基本分不出**（0~1 例），要原始波形做包络才分得开（7 例） | `AI-56`、`H-260`；[research/sca-scalar](../research/sca-scalar/README.md) |
| 2 | 边缘层「本地 FFT 频谱提取」、D05「时域波形与 FFT 同屏」、A04「支持高频波形」 | 同上，无波形可做 FFT | 同上 |
| 3 | 压机实时量 100 ms | OPC 通道**有意忽略 ScanRate**，现网实测采样 100~1000 ms。压装 2~5 秒，最坏只剩 2~5 点 —— 正是方案 3.3.1 自己说的「退化为仅能做终点值判定」 | `D-270` |
| 4 | 「仅在压装窗口采集」「每件随完成信号触发」 | 需要**压装开关点**，其 PLC 节点地址至今没有；双方约定**不得**由 `pm01_ad` 运动段反推 | F10② |
| 5 | 点位中文名 | **两处名实对调**：振动 `_f` 标「速度」、`_v` 标「频率」（三轴一致）；伺服 `_temp` 标「扭矩」、`_torq` 标「温度」。方案对伺服那处加了注，**振动那处没注**。不核实就不知道绑哪个点作速度 | 方案 3.3.2 注；我方 `AI-64 §1.1` |
| 6 | 19 点、伺服 1 台 | 现场点表 **54 点**：伺服 **A10~A21 共 12 台**；振动 13 点**同址重复建了一套** | 网关侧方案 §1 |
| 7 | 「故障提前 2~4 周」各项预警提前量 | 无健康基线、无故障样本，现场一条真实数据都没有，**提前量无出处** | F8 |

★第 1、2 条若要兑现，只能**换带原始波形的传感器**（如维特 VB02 带 `RAWFIFO`，未采购）；否则把「轴承故障」与「FFT」降级表述为「趋势与方向性提示」。

## 5 预案：前置到了之后我方做什么

按「触发条件 → 动作」排。★**触发前一律不落码**。新增域 = 丢一个 `domains/*.py`，骨架不改。

| # | 动作 | 触发条件 | 要点 / 未定处 |
| --- | --- | --- | --- |
| P1 | **结构值读侧接线**（F1：`fetch.py` 填 `Frame.structs`、按字段绑定） | 现在即可做 | 压机一切的前提；不依赖现场 |
| P2 | **振动两域绑到北自所点上** | S1 + S2 + S3 + S7 | 代码不用改，是配置。缺哪项参数域自己落对应坏码。烈度判级只看速度 |
| P3 | **压机域重写**（F2） | P1 + S1 + S2 + S4；且压机四点读出非零值（F11） | 先做**不要模型**的一层：终点判据（`fd`/`ff` 对目标值）、形态特征（压装功、斜率、台阶、起始点）；包络比对另需 S5。模型层仍走外部导入，**喂哪段待定**（F3）。`PM_PressFit` 注册同样等 F11 |
| P4 | **伺服「扭矩 + 温度」趋势域**（新域，与 `servo_health` 并存） | S1 + S2 + S3，且 U2 定了要做 | 输入 2 路 1 s；判据即方案 3.4.5 交叉印证表（同向 ↑ 才指向轴承）。**12 台同型可做同工位对比**以排共因（方案 3.4.6 的思路）。趋势要跨帧状态（README §22 已有那一格） |
| P5 | **SPC** | U1 定了归我方 | 若归我方：可作一个域，控制限与子组状态走跨帧状态；8 条规则是确定性算法，无须训练 |
| P6 | 振动四分类 | 换传感器（§3 #1） | 在现有传感器上**不做**。不平衡 / 不对中维持「方向性提示」 |
