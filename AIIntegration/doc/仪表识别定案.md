# 仪表识别定案

> 2026-09-17 用户定。三个模块在概念上统称「图像识别」，配置时选用哪个算法；同一张图可串行配置多个算法、各出各的结果（此前已定）。

## 一、实体：由 AICloud 增加三种表计实体类别

| 实体类别 | 对应识别算法 |
| --- | --- |
| **指针表计** | 指针表读数（原 `pointer_meter_service`） |
| **数字表计** | 数字表读数（原 `digital_meter_service`） |
| **OCR 表计** | 通用 OCR（原 `ocr`） |

★由此，读表按「表计实体」配置：每块表是一个实体，读数结论点属于这块表。
本需求已于 2026-09-17 以 `AI-47` 告知 AICloud。

## 二、逐项结论

| # | 事项 | 结论 |
| --- | --- | --- |
| M1 | 图从哪来 | 两路：**上传图片**；**视频流上定时取帧读数**（按视频定案） |
| M2 | 一张图里有多块表 | **每块表各出一个读数**：配置时在画面上框出该表位置，读数写到该表计实体的结论点 |
| M3 | 单位 | **每块表配置自己的单位**（原项目指针表写死 `MPa`） |
| M4 | 指针表校准 | **校准角度、表盘总角度作为每块表的参数**，默认 5°、270°（原项目写死 270°） |
| M5 | 数字表依赖另一个 OCR 服务 | **数字表内部串「区域检测 → 文字识别」**，不走 HTTP、不依赖另一个服务 |
| M6 | 数字表允许字符 | **作为参数**，默认 `0123456789.:-+` |
| M7 | 结论怎么写 | ★**三种都把结论点写入实时库（VQT）**：指针表、数字表写读数；**OCR 表计也写**（文字结果按字符串值写入） |
| M8 | 图片留存 | 每次读数留**读数结果图**；★**中间过程图（检测框图、裁剪图、矫正图等）可选存入实时库**，由配置开关决定 |
| M9 | 推理框架 | **先照搬原项目常驻版**（torch / ultralytics / paddle），保证功能齐全；转 ONNX 以后再做 |

## 三、依赖

- 图片存入实时库依赖 historystore 的**独立媒体接口**（★2026-09-18 `H-246 §3` 改：方案已定稿，不叫 Blob 引擎、不经 `PostVQT`；单对象默认上限 64 MB，按点设保留天数，新对象有只推元数据的订阅）。**仍须等 hs 实现并宣告能力位后才能落码**；在此之前，结论点（数值、字符串）可先写，图片留存暂不可用。详见 [README §21.4](../README.md)。
- 视频流取帧依赖视频定案的取帧器与跨帧状态（实施顺序 ③、⑦）。
