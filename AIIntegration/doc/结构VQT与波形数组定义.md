# 结构 VQT 与波形数组 —— 定义

> 2026-09-19 定。**这是地基**：它定错了，振动算法怎么实现都是错的。
> 全部论断以 FEMTO 真语料实测为锚（`D:\download\AIRef\datasets\femto`），不引推测。

---

## 0 两条定义

### 定义一：结构 VQT = **一个时刻**测到的多个具名量

```
VQT ┌─ T   时间戳 —— ★**一个时刻**，不是一段时间
    ├─ Q   质量码 —— 这条记录可不可信
    └─ V   值
         · 标量 VQT：一个数
         · 结构 VQT：一组具名字段（同一时刻的多路）
```

★**T 和 Q 仍归 VQT，不进结构。** 结构只装"这一刻的量"。

### 定义二：波形 = **一个连续时间段内、结构 VQT 的数组**

★**「帧」不是存储对象，是一段时间范围的查询结果** —— 是**视图**，不是**实体**。

```
按时间范围取 ──▶ [VQT, VQT, VQT, …]  ← 这就是一帧
                  ↑每条一个真实时刻
```

### ★适用边界（验证 1 查出，2026-09-19）

本定义的全部推论都建立在一个前提上：**每条样本有自己的真实时刻**。
这个前提**不是普遍成立的**：

| 源 | 逐样本时刻 | 采样率从哪来 |
| --- | --- | --- |
| **FEMTO** | ★**有**（时,分,秒,微秒） | 可从 T 推出 |
| **CWRU** | 无（纯数组） | ★只写在**目录名**里（`12k_` / `48k_`） |
| **MAFAULDA** | ★**无**（纯数组，首行就是 6 个数） | 标称值，文档里 |

⇒ **公开数据集多为离线文件，不打时标**；而**我方要接的是在线采集链路** ——
时标由采集侧在读到那一刻打（FEMTO 属于这一类）。

★**所以本定义适用于我方的场景，但不能反过来说"振动数据都该这样"** ——
对着一个没有逐样本时刻的离线文件谈"采样率从 T 推出"是无从谈起的。
离线数据集进我方系统时，时标要在**导入那一刻**按标称采样率生成，
并**明确记下这是生成的、不是测量的**。

## 2 一行怎么映射

```
一行  9,39,39,65664, 0.552, -0.146
      └──────┬─────┘  └──────┬──────┘
         VQT 的 T        结构的 2 个字段
      09:39:39.065664   水平=0.552  垂直=-0.146
```

| CSV 的列 | 去哪 |
| --- | --- |
| 时,分,秒,微秒 | **VQT 的 T**（不进结构） |
| 水平加速度、垂直加速度 | **结构的两个字段** |
| —— | Q 由采集侧给 |

⇒ **一行 = 一个同时刻的完整采集记录 = 一条结构 VQT。**

## 3 由定义推出的六条（硬推论，不是偏好）

| # | 推论 | 为什么 |
| --- | --- | --- |
| 1 | **一个采样瞬间 = 一条结构 VQT** | T 是一个时刻，所以一条记录只能代表一个时刻 |
| 2 | ★**采样率不存，也不该存** | 相邻两条 VQT 的 T 之差就是采样间隔。另存一个 `sampleRate` 字段 = 制造**两个可能不一致的事实源**，元数据说 25.6 kHz 而 T 序列说别的，信哪个？ |
| 3 | ★**帧边界不存** | T 序列里的空档就是边界（FEMTO：连续 2560 条间隔 39 μs，然后跳 9.9 秒）。边界是**数据本身的事实**，不是需要另行声明的元数据 |
| 4 | **多路同步由"同一条记录"保证** | 水平与垂直在同一个 V 里，不可能各自漂。比两条独立标量时序强得多 |
| 5 | ★★**等间隔成为可验证的，而不是靠信任** | 算法拿到数组，**自己看 T 就知道等不等间隔** |
| 6 | **读侧一行都不用改** | hs 的 `QueryHistory` + `kRawData` 本来就是"给时间范围、回一串 VQT"，返回类型就叫 `VQTArrayRes` |

### 3.1 ★推论 5 为什么是决定性的

振动数据**不能用 SDT**（旋转门压缩）：它按值的形状丢样本，丢完**采样间隔就不等了**，
而 FFT、包络解调、阶次分析的前提全是等间隔。丢的还恰恰是峰值。

- 若把一帧塞进**一个** VQT：采样率是声明出来的。声明与实际不符时，**没有任何办法发现** ——
  曲线照样画得出，谱照样算得出，只是**全错**；
- 按本定义（**数组**）：采样间隔是 T 序列**量出来**的。`compErr`/`frozenSec` 若没设成 0 而丢了样本，
  T 序列立刻出现不该有的空档，**算法当场看得出**。

⇒ **把"必须等间隔"从一条靠人记住的配置纪律，变成一条数据自证的事实。**

## 5 结构因此变得极小

```
VibSample（振动，双通道）        VibSample3（三轴）
  水平加速度  f32                  x  f32
  垂直加速度  f32                  y  f32
                                   z  f32
```

**没有** `sampleRate`、**没有** `channelNames`、**没有**帧长、**没有** `triggerReason`
—— 它们要么是数据本身的事实（推论 2、3），要么根本不是"这一时刻的量"。

★此前我方拟的字段表越写越臃肿，根因是**在给一个不该存在的实体（帧）设计元数据**。

## 6 一处例外：事件型数据

| 类型 | 一条 VQT 是什么 | 例 |
| --- | --- | --- |
| **连续采样** | **一个采样瞬间** | 振动波形、温度 |
| **事件型** | **一个事件** | 一次压装 |

压装曲线的横轴是**位移不是时间**；"这一次压装"确实是一个时刻发生的一件事，
整条曲线是**这个事件的属性**。⇒ `PressCurve` 做成一个值**说得通**，波形做成一个值**说不通**。

★判据甲：**这一条记录的 T，对它装的全部内容都成立吗？**
- 波形帧：不成立（2559 个采样各有各的时刻）⇒ 必须拆
- 一次压装：成立（事件发生在那一刻，曲线是它的属性）⇒ 可以整装

## 6.1 ★判据甲只回答"能不能"，不回答"该不该"（2026-09-19 用户验证查出）

用户拿**现场在用的有人 USR-SVT10-01B** 来套本定义，查出判据甲有缺口。

那款一次 Modbus 读回 13 个寄存器（温度 + 三轴 × {速度,加速度,位移,频率}），
**全部出自同一个 500 ms 检测周期** ⇒ 判据甲说**成立**，可以整装成一个结构。
★**但它不该做成结构** —— 本定义的三条收益，对它一条都不成立：

| 收益 | 对有人 SVT10 |
| --- | --- |
| 采样率从 T 自证 | 2 Hz 慢变量，**算法根本不依赖间隔** |
| 丢样可检出 | 它**本来就该被 SDT 抑制**（温度不变就不写是对的）；丢中间点不破坏任何东西——**没有谱可算** |
| 多通道同步 | ★**实测不需要**（见下） |

第三条查过码，不是推测：`vibration_iso` 的 `axial_ratio` 与
`vibration_baseline` 的 `ratio_drift`，**两个跨轴比值用的都是窗口内逐轴最大值 `peaks`，
没有任何一处做逐样本配对**；骨架 `fetch.py` 也只按 role 各取各的序列，
`Frame` 文档串里说的"对齐"实际只是**共同时间窗**。

而代价是实的：**13 个标量测点在 AICloud 现有趋势与报警里直接可见可用，
塞进一个结构值就都看不见了**（字段级访问还没有）。

### ⇒ 补上判据乙

> **★判据乙：算法是否依赖「这些量出自同一瞬时」或「样本等间隔」？**
> - **不依赖**（窗口统计：最大 / 均值 / Z 分数）⇒ **保持标量测点**，不做结构
> - **依赖**（谱分析、瞬时比值、相位、曲线形状）⇒ **必须结构**

**两条判据的分工**：甲判**合法性**（装进去语义对不对），乙判**必要性**（值不值得装）。
**两条都过才做结构。**

| 对象 | 甲（能不能） | 乙（该不该） | 结论 |
| --- | --- | --- | --- |
| FEMTO 波形一行 | 成立 | 依赖等间隔 | ★**结构** |
| 维特 `RAWFIFO` | 成立 | 依赖等间隔 | ★**结构** |
| 一次压装 | 成立 | 依赖曲线形状 | ★**结构** |
| **有人 SVT10 的 13 个量** | 成立 | **不依赖** | ★**标量测点** |

★只有判据甲时，上表四行**全判"可以"** —— 那就等于没判。

### ★附带查出：T 的语义两者不同

FEMTO 的 T 是**采样瞬时**；有人的 T 是 **500 ms 检测周期的末时刻**
（周期内传感器自己算完 RMS/FFT 才吐结果）。
两者都满足「T 是结论所依据数据的时刻」，但**前者可推采样率，后者推出来的只是上传节拍** ——
这是 §0「适用边界」那条的又一个实例。

### 若将来仍要为它定一个结构（按 S1/S2 的形态）

两点先说死：

1. ★**名字不能叫 `USR_SVT10_01B`** —— `结构值点定案` S2 明写「按用途一份、全网共用、
   **不为每台设备建结构**」。该叫 `AI_VibScalar`，01A（4 项）与 01B（13 项）的差别用
   **字段可不填**吸收，**不是两个结构、也不是两个版本**。
2. ★**`vel_is_rms`、量程、精度不进结构** —— 它们是传感器型号与标定的属性、恒定不变，
   属于绑定参数（现在就在 `ParamSpec` 里）。这是 §5「结构会变得很小」那条。

```
AI_VibScalar  v1                    ── 净载荷 52 B
  temp_c                  f32  ℃      原值/10
  vel_x   vel_y   vel_z   f32  mm/s   原值/10
  acc_x   acc_y   acc_z   f32  g      原值×0.01
  disp_x  disp_y  disp_z  f32  μm     原值×1
  freq_x  freq_y  freq_z  f32  Hz     原值×1
```

★**存标度后的物理量、不存 i16 原寄存器值** —— 原值要靠型号才解得出，
而结构按 S2 是全网共用的，不能把某一款的标度焊进去。

## 7 唯一要盯住的代价

逐行一条 VQT，记录数是大的：FEMTO 节拍下 **256 条/秒/传感器**（2560 行 ÷ 10 秒）。
每条要带 TagId + T + Q + StructId + 版本，而**结构值吃不到 Gorilla 列式压缩**
（hs 的 `gorilla_codec` 只处理 R8/R4/整数，结构值退到 gzip）。

★**这不是否定本定义的理由**（语义正确优先），但它是**唯一要盯的一处**，且有得谈：
可请 hs 评估结构值能否也走列式编码 —— 同一结构、同一质量的一段连续记录，
字段逐列压缩的条件是具备的。

脚本在 `research/struct-vqt-verify/`：`verify.py`、`verify2_threshold.py`、
`verify3_algorithm.py`、`verify145_others.py`。

| # | 验什么 | 结果 |
| --- | --- | --- |
| ① | 帧能否**只凭 T 序列**浮现 | ✅ 3 个文件拼成 7680 条序列，**切回 3 帧 × 2560**。全程未用采样率/帧长/文件名 |
| ② | ★判别阈值有没有**分离带** | ✅ 见 §8.2 |
| ③ | ★丢样对算法的**破坏有多大** | ✅ 见 §8.3 |

| ⑤ | 跨整条寿命（含失效段） | ✅ 见 §8.4 |

### 8.1 ★两次被真数据纠正的统计量（写下来，免得再犯）

**第一次**：用**众数**推采样率，得 25,000 Hz、偏 2.3%。查分布才明白真实间隔
`1/25600 = 39.0625 μs` 而**时间戳只有 1 μs 分辨率** ⇒ 必然在 39/40 抖动
（实测 40×1575、39×825，另有 158 个 30 μs 时钟毛刺）。⇒ 改用**整帧平均**，得 25,601.3 Hz、偏 0.005%。

**第二次**：验"丢样可发现"时用**相对整段平均的偏离**做判据，跑出"**无分离带、论断不成立**"。
查下来是**方法错**：★**抽稀会把平均一起抬高 —— 基准跟着被污染，效应自我抵消**。
⇒ 改用**间隔 ÷ 低分位基准**（抽稀**不会制造更短的间隔**，低分位对抽稀免疫），分离带立刻成立。

★**教训：基准怎么取，比判据本身更容易错。** 两次都是同一类错。

### 8.2 ★验证 ②：分离带（300 帧、767,700 个间隔全扫）

| | 间隔 ÷ 基准 |
| --- | --- |
| **完好数据** | 最大 **1.051**（时钟毛刺那 47,400 次在 0.8 倍，在基准**之下**，不误报）|
| **抽稀 0.5%**（只丢 12 条） | 立刻出现 **2.05 倍**，检出 12 处 |
| 抽稀 29% | 最大 **7.95 倍**，检出 510 处 |

⇒ **分离带 = (1.05, 2.0)**，中间空着一倍宽。判据定死：

> **存在 >1.5 倍基准间隔者 ⇒ 这段数据被丢过样本。**

### 8.3 ★★验证 ③：丢样对频谱的破坏（这条最值得记）

同一帧，抽稀后**当作等间隔**算谱（即「一帧一个值」路径必然会做的事）：

| 丢样 | 主峰漂移 | 谱形误差 |
| --- | --- | --- |
| **0.5%**（12 条） | 17.8 Hz | ★**53.1%** |
| 1.1% | 221.2 Hz | 68.9% |
| 8.2% | 207.9 Hz | 72.9% |
| 29.4% | **676.1 Hz** | **92.3%** |

★**只丢 0.5% 的样本，谱形就错了一半**；而这个谱**照样算得出、照样画得出、没有任何报错或坏码**，
主峰还落在 3787 Hz 这种"看起来很合理"的位置上。

⇒ 这把「振动不能用 SDT」从一句原则，变成了**有数字的事实**：
**不是"干扰"，是从 0.5% 丢样起就已面目全非，而且看不出来。**

| | 一帧一个值 | 数组形态 |
| --- | --- | --- |
| 采样率来源 | **声明**的 | 从 T **量**出来的 |
| 丢了样本 | 按声明的率照算 ⇒ 上表那些错谱 | >1.5 倍间隔立刻暴露 |
| 结果 | **静默给出错结论** | **可以拒绝出结论** |

### 8.4 验证 ⑤：跨整条寿命

取第 1 / 701 / 1402 / 2103 / 2803 帧（覆盖健康到失效）：

- 推出采样率**全部 25,601.3 Hz**，无漂移；
- 最大倍数**全部 1.051**，帧完整性不因工况而变；
- 幅值 RMS 从 0.56 → 5.61（末段增大 10 倍，确是失效段）。

⇒ **采样率推导与丢样检测在失效段同样成立**，不受幅值剧变影响。

### 8.5 验证 ④：代价（唯一要盯的一处）

一条结构 VQT ≈ **34 字节**（TagId 4 + T 9 + Q 3 + StructVal 头 2 + StructId 2 +
版本 2 + Data 头 2 + 两个 f32 字段 10），净载荷只有 8 字节 ⇒ **膨胀 4.2 倍**。

本轴承 7,175,680 条 ⇒ **244 MB**，而「一帧一个值」只要 57.5 MB。**数组形态是它的 4.2 倍。**

★**但这是未压缩的估算。** 结构值目前退到 gzip；★**若 hs 给结构值也做列式编码**
（同结构、同质量的连续段逐列压），差距会明显收窄：**T 走 delta-of-delta 几乎免费、
Q 整段一份、两个 f32 列各自 XOR** —— 这正是标量点已经享受到的 Gorilla 待遇。
⇒ **这是值得向 hs 提的一条**，而不是接受 4.2 倍就完了。

### 8.6 ⇒ 总结论

**帧、采样率、帧周期三样全部是数据自证的**，一个元数据字段都不需要；
**丢样可检出**（分离带 1.05↔2.0）；**丢样的破坏已量化**（0.5% → 谱形错 53%）。

定义成立，**但有适用边界**（见 §0 定义二下方）：它要求源**逐样本打时标**。
