## 0 一句话

现场入库的振动 / 伺服 / 压装**全是标量点**，而 `AI-59` 定的结构 VQT 要「一个时刻测到的多个具名量」。

★**把"这一条是真同刻，还是拼出来的"写进数据里**，让消费方看得见。拼出来的也能用，但不能冒充测到的。

## 2 ★先说清一件：组装**不产生**波形

`AI-56` 已报过、`H-260` 也实测认过：**现场那款振动传感器结构上就不产原始波形**，OPC UA 上挂出来的

⇒ 把 13 个标量组装成一条结构，得到的是**「某一时刻的 13 个特征量」**，不是一帧波形。
波形那条线仍**待料**，卡在数据源，不卡在本方案。谁都别指望这一步能把它解开。

## 3 为什么放在网关

| 放哪 | 判断 |
| --- | --- |
| ★**采集侧（daqgate）** | **唯一可行**。「同刻」这件事只有采集侧知道 —— 哪几路是同一次 Read/Publish 回来的、各自的 `SourceTimestamp` 是多少，出了网关就没了。且 `AI-59` 规则 9 / `H-262 §1` 已定「**结构由采集侧定义并注册**」 |
| 实时库（hs） | 不行。hs 收到的已经是各点独立的 VQT，同刻性早已丢失；且 hs 明确「不解释语义」（定稿 #21） |
| 消费侧（我方按 T 对齐） | 不行，且**看起来行**才危险：各成员点各带 `compErr=0.01` / `frozenSec=60` 的死区，**落库的 T 网格各不相同**，对齐只能插值 —— 插出来的"同刻"无从证伪。这正是定义 §1 反对「声明的时刻」的同一条理由 |

## 4 机制：网关侧的「组装器」

### 4.1 配置形态

一个**组装单元** = 一个新建的结构点 + 一张成员表：

```
结构点  bzs_pm01_curve        Acc=36(VT_RECORD)  StructRef=<结构名>
  ├─ 字段 position ← 成员点 1835 bzs_pm01_ad   quantity=displacement  unit=mm
  └─ 字段 force    ← 成员点 1836 bzs_pm01_af   quantity=force         unit=N
组装模式 Assembly=same-response      时标 TsSource=measured
```

- 成员**必须同通道、同 `ScanRate`**（否则违反 `AI-59` 规则 4：采样率不同的量另建点）；
- 字段名、结构名**由贵方取**，我方不占名（规则 9、`AI-59 §2.0`）；
- 我方只要求字段带 `quantity` / `axis` / `unit`（`H-261 §2.1` 的约定键），**按字段绑定、按 `quantity`+`unit` 核对，不换算、只拒绝**。

### 4.2 ★同刻判据：三种组装模式，可信度递减

| 模式 | 怎么组 | T | 同刻性 |
| --- | --- | --- | --- |
| ★**M1 同响应** `same-response` | 全部成员在**同一次采集响应**里返回，且 `SourceTimestamp` **全等** | 该 `SourceTimestamp` | **真同刻**。唯一"测到的" |
| **M1′ 同响应带偏差** `same-response-skew:<ε µs>` | 同上，但源时刻不全等，极差 ≤ ε | 取**最晚**的一个 | 近似。偏差有**上界且写在点上** |
| **M2 主字段触发** `lkv:<陈旧上限 ms>` | 指定一个主字段，它一更新就出一条；其余取各自**最新缓存值** | 主字段的 `SourceTimestamp` | **拼的**。其余各路最陈旧 = 上限 |
| **M3 定时快照** `snapshot:<周期 ms>` | 网关按固定周期取各成员最新值组一条 | **网关时钟生成** | 最不可信 |

**M1′ 为什么取最晚而不是最早**：一条结构值的语义是「**截至 T，这几路的测量**」。
取最晚 ⇒ 记录里**没有任何一路的值来自 T 之后**，最坏情况只是某一路陈旧了 ε；
取最早则相反，等于宣称在 T 那一刻就已知道 T 之后才测到的值 —— 那是**凭空的预知**，不能接受。

**优先级**：M1 > M1′ > M2 > M3。
★我方**不接受 M3 作为压装或振动的来源**；它只在源确实给不出 `SourceTimestamp` 时才有意义。

### 4.3 组装模式要写进数据 ⇒ 建议新增 `Paras` 键 `Assembly`

`H-262 §2.2` 已给结构点定了四个键：`Acc` / `StructRef` / `ProcChain` / `TsSource`。
**`TsSource` 只收 `measured` / `generated`**（`H-261 §3`，锁死），它答的是「T 从哪来」，
**答不了「这几路是不是真同刻」** —— M1、M1′、M2 三种的 `TsSource` 都是 `measured`，可信度差着量级。

⇒ 提议加第五个键：

| 键 | 取值 | 规则 |
| --- | --- | --- |
| ★`Assembly` | `native`（源本身就是结构，无组装）/ `same-response` / `same-response-skew:<µs>` / `lkv:<ms>` / `snapshot:<ms>` | 与 `ProcChain` / `TsSource` **同一条**：首次非空即落定，之后改了整批拒 —— 口径一变，同一个点前后两段数据含义不同 |

- ★**若 hs 不愿再加一把锁**，退而求其次：**折进 `ProcChain` 串**（它本就是自由串、本就已锁），
  写成 `raw;assembly=same-response`。我方解析得了，代价是 `ProcChain` 一串两义。**两条都行，请 hs 与贵方择一**；
- 缺这个键时我方按**最坏**（`snapshot`）对待，即：**不据以出质量 OK 的结论**（我方硬规矩 4）。

### 4.4 Q 的合并 —— 一路坏，整条坏

`AI-59` 规则 5、`H-262 §1` 第 4 条：**一路缺了整条置坏 Q，绝不以 0 或 NaN 代替"没测"**。落到组装器：

| 情形 | 处置 |
| --- | --- |
| 各成员 `StatusCode` 都好 | 结构 Q = 好 |
| 任一成员坏 / 不确定 | 结构 Q = **各成员里最差的那个**，记录**照写**（字段填该路最后一个值） |
| 任一成员在本轮**没返回** | 整条置坏 Q。★**不得跳过该字段** —— hs 无可选字段，未填的 float 读出来是 `0.0`（`H-261 §1` 事实 3），跳过等于悄悄写了个 0 |
| M2 下某成员陈旧超过上限 | 同上，整条置坏 Q |

### 4.5 ★取值必须取在死区**之前**

现有成员点都带 `compErr=0.01`、`frozenSec=60`。这是**存储侧**的死区。
组装器必须取**通道本轮采到的原始值**，不能取死区过滤后的值：

- 过滤后各路"有没有新值"各不相同，M1 的「同一次响应」当场瓦解；
- 结构值点在 hs 侧本就**强制逐字档、不做 SDT、不做等值去重**（`H-261 §5.1`），
  上游再压一道，压掉的就永久没了。

⇒ 请贵方确认组装器在数据通路上的**插入位置**在死区之前。

### 4.6 成员点的去留：结构点一律**新建**，老点**不动**

★**不能把已有标量点"改型"成结构点**：`Acc` 从 `4`/`18` 改成 `36` 是换型，而 `StructRef` 绑定后不许换绑（`H-262 §2.2`）；
这批点已在现场入库、已有消费方（AICloud 的趋势与报警）。

⇒ **结构点是新增点，成员标量点原样保留**，两份并存。代价是容量，但：

- 结构值已有列式编码 `'S'`，实测落盘 **4.65 字节/条**（`H-261 §4.2`）；
- 本期只新增**一个**结构点（§5），增量可忽略；
- 换来的是零破坏：现有趋势、报警、界面一处不动。

### 4.7 注册与能力位

- 结构由贵方在**启动时自动注册**、幂等（`AI-59 §4` 规则 5）；改 `attrs` 也算改描述 ⇒ 发新版本（`H-262 §2.1`）；
- 写之前**探能力位**：`struct-registry` / `struct-value` / `struct-stream-attrs`（认不认 `ProcChain`/`TsSource` 的锁）/ `struct-columnar`（`H-262 §2.3`）；
- 降级下限见 `H-262 §3.2` 与 `H-263`（`H-263` 请改投 `1.9.495` 而非 `1.9.493`）；
- 结构值点按 `H-257` 走**推点方自带 guid** 建。

## 5 ★把这张点表逐组判一遍

判据只有两条，都出自 `AI-59 §2.1`：

> **规则 4**：只装**同一时刻都有测量值**的量，采样率不同的另建点。
> **规则 8**：算法只做**窗口统计**的量，**保持普通标量测点**，不做结构。

| 组 | 判 | 为什么 |
| --- | --- | --- |
| 振动 A01 `bzs_v1_*`（13 点） | ★**不转** | 已是厂家算好的**特征量**，1 Hz，我方模块 1/2 对它只做窗口统计 ⇒ 正是规则 8 说的那类。转了也拿不到波形（§2），却要新增一个点、再付一份存储 |
| 第二套 `vb_svra10_v1_*`（13 点） | **先核实** | 与上一组同址（§1.1 第 1 条）。定了以哪套为准再谈别的 |
| 压机 `pm01_ad` + `pm01_af`（2 点） | ★**转** | 位移与力**必须同刻**才是一条压装曲线 —— 这正是结构点存在的理由。但有前置条件，见 §6 |
| 压机 `pm01_fd` + `pm01_ff`（2 点） | **不转** | 「最终位移 / 最终力」是**一次压装出一个**的结果量，与实时量节奏完全不同 ⇒ 规则 4。它们本身就该是标量，且是现成的压装结论旁证 |

⇒ **本期只新增一个结构点**。这不是保守，是按定的规则判出来的：
结构点的成本（不去重、逐字档、新增点、口径一旦落定就锁死）只有在**"同刻"真的是算法前提**时才值得付。

## 6 压机：本期唯一值得转的一组，但卡两个前置条件

### 6.1 结构（字段由贵方定名，下表是我方要的**语义**）

| 字段语义 | `quantity` | `unit` | 来源点 |
| --- | --- | --- | --- |
| 位移 | `displacement` | `mm` | `1835 bzs_pm01_ad` |
| 力 | `force` | `N` | `1836 bzs_pm01_af` |

### 6.2 ★前置一：采样率。现在是 `ScanRate=1`，压装曲线要不出来

一次压装是**秒级**的事。`ScanRate=1`（★单位请贵方确认：秒 / 毫秒 / 档位）意味着一条曲线上只有个位数的点，
压入、保压、回程三段切不开，"压装不到位"判不了。

⇒ **请贵方答**：这条 OPC UA 链路（经 KEPServer）压机那两个节点能到多快？PLC 侧有没有更快的路
（直连 PLC 驱动 / PLC 内部高速缓冲成批上传）？

**够不够的量级**：我方要**≥ 100 Hz**才谈得上曲线形状；`H-261 §5.3` 已确认 hs 单点无速率上限（开发机实测 ≈ 17 万条/秒），
**瓶颈不在实时库**。若到不了，压装这条线**仍待料**，本方案其余部分不受影响。

### 6.3 ★前置二：压装的起止，要一个开关点（这件我方欠贵方一封函）

`AI-59 §2.1` 规则 7 与 `H-262 §1` 第 7 条都写了「一次压装的起止由一个标量开关点给，细节 AIIntegration 另函致 daqgate」——
**那封函我方一直没发**（记在 [暂缓与未定事项](暂缓与未定事项.md) 二之五 F4）。细节就是下面这些：

| 项 | 要求 |
| --- | --- |
| 形态 | **一个标量点**，压装开始写 ON、结束写 OFF。点表里现在没有这个点 |
| ★存法 | **逐变化都存**，ON / OFF **一条都不能被压掉** ⇒ `compErr=0`、`frozenSec=0`、`persist=1`。★现有点一律 `compErr=0.01`/`frozenSec=60`，**照抄这套参数会把 ON/OFF 压没**，时段就断了头尾 |
| 为什么必须有 | 结构 VQT 数组**自己不声明边界**（定义推论 3）。开关点在 hs 里的历史，**就是**每次压装的起止时刻表 —— 它是时段的**唯一**来源 |
| 三段 | 开关点只给 ON/OFF；压入 / 保压 / 回程**由我方域按时间顺序切分**，不要贵方切 |
| 来源 | 若 PLC 里已有"压装中"这类信号，直接建点即可；没有则请贵方给一条可用的判据 |

## 11 ★★订正 §10.3：那 97.9% 是**后备批量读的产物**（2026-09-23 晚，`D-271` 异议成立）

`D-271 §3` 指出：`1835 ad` 与 `1836 af` **id 相邻、同通道、同 `frozenSec`**，
几乎总在**同一次后备批量 `Read`** 里回来 ⇒ 服务端给同一个时刻 ⇒ 逐位同刻。
**与"两路同时变化、服务端同响应推送"无关。**

我方设计了一个能**证伪**它的判据，跑下来**证实了 daqgate**。

### 11.1 判据

后备读按到期时间凑满 50 点一批，**不管点属于哪台设备、量的是什么**
⇒ 若假说成立，**物理上绝无可能同刻**的量也该大面积逐位同刻。

### 11.2 结果（只好值，168 小时窗口）

| 比对 | 好值 | 逐位同刻 | 错开中位 |
| --- | --- | --- | --- |
| 对照：压机 `ad` vs `af`（§10.3 那一对） | 95 / 95 | **97.9%** | 0 µs |
| 同设备：`ad`（实时位移） vs `fd`（**最终**位移） | 95 / 95 | **96.8%** | 0 µs |
| ★跨设备：压机 `ad` vs 伺服 **A10** 温度 | 95 / 107 | **54.7%** | **0 µs** |
| ★跨设备：伺服 **A10** vs 伺服 **A21** 温度 | 107 / 96 | **78.1%** | **0 µs** |
| 压机 `ad` vs 振动 `x_acc` | 95 / 5052 | 0.0% | 4.34 s |
| 对照：振动 `x` vs `y` | 5052 / 5052 | **96.2%** | 0 µs |
| 对照：振动 `x` vs `z` | 5052 / 6176 | **1.8%** | 14.4 s |

★「实时位移 vs **最终**位移」96.8%、「两台**不同**伺服电机的温度」78.1%、错开中位都是 **0 µs** ——
这些量**不可能**真的在同一微秒被测到。**只可能是同一次读回来的。**

### 11.3 ⇒ §10.3 的结论改口

| 原 | 改 |
| --- | --- |
| 压机那一对 97.9% 逐位同刻 ⇒ **`M1` 基本成立** | ★只证明**后备读路径上 `M1` 是结构性的**；**压装过程中的 `M1` 未证** —— 压机真在动时值频繁变化，走的是**订阅**路径，轮不到后备读 |

### 11.4 ★`x`/`y`/`z` 那组反常是同一条机理的另一面

| | 落库行 | 好值 | 走哪条路 |
| --- | --- | --- | --- |
| `x_acc` / `y_acc` | 7239 | 5052 | 变化少 ⇒ 常满 `frozenSec` ⇒ **多走后备读** ⇒ 同批 ⇒ 互相同刻 |
| `z_acc` | **8363** | **6176** | 变化多 ⇒ **多走订阅** ⇒ 各自时刻 ⇒ 与 x/y 不同网格 |

⇒ §10.4 的结论由「**死区**把同刻性打散」修正为「**路径**决定同刻性，死区只是决定走哪条路的开关」。

### 11.5 ★对 `Assembly` 取值的硬结论

同一个点**静止期走后备读（真 `M1`）、运动期走订阅（未知）**，而 `Assembly` 是**首次非空即永久锁死**的。

> ★**在订阅路径的同刻性量到之前，`PM_PressFit` 的 `Assembly` 不得填 `same-response`。**
> 按最坏工况填（`lkv:<上限>` 或保守的 `same-response-skew:<ε>`）。
> 按静止期填 `same-response`，会让**唯一有用的那段数据**（真在压的那几秒）顶着一个它当不起的标签 ——
> 我方据此出质量 OK 的结论，正是硬规矩 4 禁止的事。
