# AI 诊断模块说明：振动 / 伺服 / 压装 / 变频器

> 给协作同事看的总览（AICloud、daqgate、historystore 及其他工程同事）。
> 2026-09-18。只讲**编排、算法、接口、数据流转、界面配置**五件，细节与取舍理由见各自的定案文档。

---

## 0 一页看懂

AIIntegration 是一个**纯后端**服务，部署在 AISERVER。它把各类 AI 诊断统一接进 AICloud：

```
 AICloud 界面                AIIntegration（本服务）                     historystore
 ───────────                ──────────────────────────                 ────────────
 配置诊断 ──gRPC─▶  骨架 ┌─ 建结论点、推全量快照 ──────────────────▶  点表
 （绑定）             │
                      ├─ 按节拍取测点 ◀───────────────────────────  QueryHistory
                      │      │
                      │      ▼  成帧（数据+质量码+真实时刻）
                      │   算法域 .py  ← 工件（模型/基线）、跨帧状态由骨架喂
                      │      │
                      │      ▼  Finding(值,质量,时刻)
 看结论 ◀──────────── └─ 写回 ──────────────────────────────────▶  PostVQT
```

三条贯穿始终的规矩：

1. **算法域不知道实时库存在** —— 不碰连接、不碰 id、不碰 VQT。它只回答"给你这段数据，结论是什么"。
2. **结论必须同时给出值、质量码、时刻**（VQT 三元组），在类型层强制，"只填值"写不出来。
3. **算不出来就落质量码，不许编一个数** —— 也不许"什么都不发"（下游会把它读成"这段没数据"，查错方向）。

## 2 逐个模块

### 2.1 经典算法振动诊断（`vibration_iso`）

| | |
| --- | --- |
| **算法** | 取窗口内三轴速度**最大值** → 按 **GB/T 6075.3**（一般机组）或 **GB/T 6075.7**（泵）查限值表 → 判烈度区 A/B/C/D；另出轴向/径向比与方向性提示 |
| **输入** | 测点 1 的 X/Y/Z 速度（X 必填）+ 温度；可选第二测点同样五路 |
| **参数** | 机器分组、支承方式、泵类别、额定功率、额定转速、速度口径确认、轴向是哪一轴、停机门槛 |
| **结论点** | `vel_max` 速度最大值、`dominant_axis` 最大值所在轴、`iso_zone` 烈度区、`iso_zone_code` 烈度区(数值)、`iso_margin` 距下一档余量、`axial_ratio` 轴向/径向比、`direction_hint` 方向性提示、`run_state` 运行状态、`evidence` 判据摘要 |
| **依赖** | **零第三方依赖**（纯 Python 标准库） |

★**判级依据已于 2026-09-18 改依国标**（原为 ISO 20816-3）。AICloud 侧设备建模同步改依同一依据 ——
两侧必须同一依据，否则同一台设备两边算出不同的区。

### 2.2 AI 模型自训振动诊断（`vibration_baseline`）

| | |
| --- | --- |
| **算法** | 先采一条**基线**（这台设备正常运行时各通道的中位数与四分位距），之后每拍算偏离：`(当前 − 中位数) / (四分位距 / 1.349)` |
| **为什么用中位数而不是均值** | 基线只有十来帧时，一两个离群值就能把标准差撑大，让之后的真偏离显得不显著 |
| **输入 / 参数** | 同模块 1（另有「采基线时认哪个标签算正常」） |
| **结论点** | `vel_z_max` 速度偏离、`ratio_drift` 三轴比例漂移、`temp_rise` 温升、`anomaly_score` 异常分、`run_state` 运行状态、`evidence` 判据摘要 |
| **依赖** | 零第三方依赖 |

★`anomaly_score` 是 **0~100 的排序用分数，不是概率**，界面请勿按百分比呈现。
★**没有基线就说没有基线**：整组落 `MODEL_NOT_LOADED`，不拿任何默认值顶。
★**样本少于 5 帧不出基线**，采基线当场失败并说清。

### 2.3 停机判定（模块 1、2 共有）

两个振动模块都有可选参数 **`stop_threshold` 停机门槛**（mm/s）：三轴速度最大值低于它 ⇒ 判停机。

- 停机时**不判烈度、不出异常分、采基线时剔除停机帧**；
- 新增结论点 **`run_state`**（运行 / 停机 / 未判）；
- ★**停机时数值类结论这一拍不写**，点上保留停机前最后一值 ⇒ **界面需凭 `run_state` 把数值置灰**，
  否则会显示成"停机时数值一直不动"。`iso_zone_code` 停机时写 0；
- **没有缺省**，不填即不判。门槛取决于设备本身，给一个"看起来合理"的数会静默停止诊断。

> 已以 `AI-49` 知会 AICloud。

### 2.4 AI 伺服/机械臂运行监测（`servo_health`）

| | |
| --- | --- |
| **算法** | 取 9 路遥测的一段窗口（现场 10 Hz、每 5 秒取最近 20 秒）→ CNN-LSTM → **正常 / 轴承退化** + 概率 |
| **输入** | 位置指令、实际位置、跟随误差、转速、转矩、Iq、电机温度、轴承温度、IGBT 温度 —— **9 路全必填** |
| **参数** | 「模型」（CNN-LSTM / 决策树 / SVM，默认 CNN-LSTM） |
| **结论点** | `verdict` 结论、`probability` 概率、`evidence` 判据摘要 |
| **依赖** | numpy、onnxruntime |

★**它不是振动诊断** —— 一个振动传感器都不用，全靠**驱动器内部寄存器**。
  要接它需要的是**驱动器通讯口**，与振动那条采集路径完全不同。
★**机械臂不单独设模块**：每个关节配一条本诊断。

### 2.5 AI 变频器（VFD）运行监测（`vfd_health`）

| | |
| --- | --- |
| **算法** | 取 15 路的 60 点窗口（1 Hz、每 10 秒取最近 60 秒）→ TCN **三个输出头** |
| **输入** | 三相输入电压 ×3、三相输出电流 ×3、输出频率、电机输出功率、输出转矩、机柜温度、变压器三相温度 ×3、功率单元 Vdc 均值与极差 —— **15 路全必填** |
| **参数** | **无**（单一模型） |
| **结论点** | `fault_type` 故障类型、`confidence` 置信度、`severity` 当前严重度、`severity_30s` / `severity_60s` / `severity_120s`、`evidence` |
| **六类** | 正常 / 冷却系统退化 / 功率单元异常 / 输出电流不平衡 / 输入电网异常 / 过载·异常负载 |
| **依赖** | numpy、onnxruntime |

★**未来严重度三条是模型直接给的**，不是本服务拿当前值外推的。

### 2.6 AI 压装机运行监测（未落码）

| | |
| --- | --- |
| **算法** | 每次压装结束触发一次，CNN-LSTM / SVM → 4 类 |
| **四类** | 正常压装 / 卡滞 / 压装不到位 / 配合间隙异常 |
| **★界面须注明** | **本模型不判：漏装、零件破裂** |
| **卡在哪** | 输入形态改了，见下 |

★**压装的输入形态已于 2026-09-18 改变**（实时库 `H-246`）：
**一次压装 = 一个结构值点**（位移、速度、力三条曲线同在一个值里），
**不再是"三个标量点 + 边界标记点"**。理由：压装横轴是**位移不是时间**，
拆成三个标量点等于强行按时间对齐；而一个值 = 一次压装，事件边界自然就有。

有意义的特征量（峰值力、RMS…）仍算完**写回标量点**，那一套现成可用。

⇒ 依赖实时库的**结构值点**能力。该能力已于 2026-09-18 点亮，但**尚未投放到现场**，
故本模块暂未落码。

## 3 算法接口（新增一个诊断要做什么）

**新增一个算法域 = 往 `domains/` 丢一个 `.py`。没有第二步** —— 不改骨架、不改路由、不改前端、不改配置。

一个域只实现两个方法：

```python
class MyDomain(Domain):
    key = "my_domain"; display = "界面上的名字"; version = "1.0.0"

    def declare(self) -> Declaration:
        """我要什么输入、要什么参数、出什么结论。★只描述语义，不写任何 id。"""

    def infer(self, frame) -> list[Finding]:
        """给一帧已经取好、对齐好、带质量码与真实时刻的数据，回结论。"""
```

- `declare()` 的内容**原样交给 AICloud**，前端据此渲染配置界面 —— 加一个参数不需要前端改代码；
- `infer()` 拿到的 `frame` 里已经有：各路采样序列、台账参数、**当前启用的工件**（模型/基线）、
  **上一拍的跨帧状态**。这些都由骨架准备好，域不碰存储；
- 可选实现 `train()`（本域支持训练）与 `validate_artifact()`（导入模型时校验）。

**结论的形状**：`Finding(key, value, quality, t)` —— **四个字段全部必填**。
`t` 是**该结论所依据的数据的时刻**，不是算完的时刻、不是写入的时刻。

**质量码**（算不出来时落哪个，界面据此呈现）：

| 码 | 含义 | 现场该查什么 |
| --- | --- | --- |
| `ok` | 可信 | —— |
| `no_input` | 一个样本都没取到 | 采集链路 |
| `input_bad` | 有样本但全不可信 | 采集链路 / 传感器 |
| `insufficient_samples` | 样本不够算 | 节拍、窗长 |
| `config_incomplete` | 必填参数/采集点没配齐 | 配置界面 |
| `model_not_loaded` | 没启用模型或基线 | 工件页 / 采基线 |
| `compute_error` | 算的过程中出错 | 模型 / 提工单 |

## 4 数据流转

```
① 配置      AICloud ──PutBinding──▶ 骨架：记下"这条诊断用哪些点、什么参数、什么节拍"
② 建点      骨架 ──PushEntityConfigs──▶ 实时库：按 declare() 的结论点建点，推**全量快照**
③ 取数      骨架 ──QueryHistory──▶ 实时库：按节拍取窗口内的采样（带质量码与真实时刻）
④ 成帧      骨架：对齐 + 附上台账参数、当前启用工件、上一拍跨帧状态
⑤ 推理      算法域 infer(frame) → [Finding, …]
⑥ 回流      骨架 ──PostVQT──▶ 实时库：写结论点
⑦ 呈现      AICloud 从实时库读结论点
```

几条与协作方直接相关的：

- **只有骨架进程写实时库**。重型推理进程（视频等）可用同一张证书**只读直连**，但不链写接口；
- **写路径断而复连、或对端换实例 ⇒ 必须重推全量快照**。引擎重启后点定义会从实体流里消失，
  而**值照样写得进**、健康口照样 ready —— 不重推就不会自愈；
- **结论点的建立是自动的**：域的 `declare()` 多一条输出，下一拍就自动补建点；
- **回溯判别**（拿历史片段用当前模型重跑一遍）**不写回实时库**，也不动线上的跨帧状态。

## 5 界面配置（振动诊断五步）

1. **在设备上加诊断** —— 一台设备同一种诊断只允许一条，多测点放进同一条里；依赖没装上的模块不在列表里显示。
2. **选采集点** —— 支持第二测点（可选一组「第二测点 X/Y/Z 速度、温度」，不配即单测点）。候选点只列本设备下的点。
3. **填参数** —— 取数节拍（间隔、窗长）默认均 60 秒、允许修改。
4. **保存生效** —— ★**必选采集点没配齐也允许保存**，界面显示缺哪几项，结论带「配置不全」质量码；**保存即启用**，另给停用按钮。
5. **采基线** —— 只对「AI 模型自训振动诊断」适用：选一段正常运行时间 → 点「采集基线」→ 完成后自动启用。标注与建训练集由后台自动做。

伺服 / VFD / 压装三类没有第 5 步，改为**导入模型工件**：在工件页上传模型 → 校验通过 → 启用。

★**导入时会做严格校验**（这三类都是外部模型）：模型必须自述**通道顺序**、**采样率**、**类别顺序**，
VFD 还要自述**归一化方式**。缺任何一项**拒收**。
理由是这几件的共同点 —— **运行期不会报错，只会给出一个看起来完全正常的错结论**：
喂错通道顺序、少做一次归一化、类别次序反了（把"正常"报成"过载"），数值上都看不出来。

## 6 现状与前置

| 模块 | 能不能用 | 卡在哪 |
| --- | --- | --- |
| 经典算法振动诊断 | ✅ 现场在跑 | —— |
| AI 模型自训振动诊断 | ✅ 现场在跑 | —— |
| AI 伺服/机械臂 | 代码就绪 | **驱动器通讯口未通**（点已建、链路未通）；且我方**没有模型权重**，需导入 |
| AI 变频器 | 代码就绪 | **现场 15 路一个点没接**；需导入模型权重 |
| AI 压装机 | 未落码 | 实时库**结构值点尚未投放到现场** |

★**伺服、VFD、压装三类，我方手上都没有可用的模型权重** —— 原项目的训练代码与数据未找到，
或权重不适合由本仓携带。这三类要真正出结论，**需要有人提供训练好的模型**（ONNX，并按 §5 自述四件事）。
