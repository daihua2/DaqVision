# 诊断配置流程定案

> 2026-09-17 用户逐项拍板。术语：界面说「设备 / 诊断 / 采集点 / 设备参数」，代码里诊断对应 `Binding`。

## 已定的前提

| 事项 | 结论 |
| --- | --- |
| 实体关系 | 设备是实体；诊断挂在设备下；诊断上记录绑定的采集点 |
| 采集点怎么选 | **用户手工选**，不做自动识别；选错由用户负责 |
| 设备固有属性 | 机组类别、支承方式、额定功率、额定转速等**填在设备上**，★**2026-09-18 改依国标**：工业机器 GB/T 6075.3-2011、泵 GB/T 6075.7-2015（`C-43`，AICloud 用户定「有国标按国标」；ISO 20816-3:2022 尚无国标版）。`AI-45`、`AI-46` 所依的 ISO 20816-3:2022 不再作判级依据 |
| 设备参数改动后 | 界面**提示用户基线失效**；后端不自动停用，由用户决定 |
| 诊断标识 `binding` 取什么 | **未定**（需与 AICloud 协商，暂缓） |

## 五步（振动诊断）

### 第 1 步　在设备上加诊断
- **1.1** 一台设备上**同一种诊断只允许一条**；多测点放进同一条诊断里。
- **1.2** 依赖没装上的模块**不在列表里显示**。

### 第 2 步　选采集点
- **2.1** 振动诊断**支持第二测点**：可选的一组「第二测点 X/Y/Z 速度、温度」，不配即单测点。依据：MAFAULDA 实测三分类两测点比单测点高 18 个百分点。
  > ★**2026-10-05 撤销**（AICloud `C-64 §2.1`，我方用户同意）：一条绑定 = 一个振动传感器，第二测点就是另一个传感器、另一条绑定；
  > 「取各测点最大」挪到平台设备层合。两个振动模块（契约 1.13）已去掉第二测点组。
  > 那 18 个百分点是分类器**合用两点特征**的收益，平台「取最差」合不出来 —— 但故障分类本就「先不做」（2.3），眼下无损失；
  > 将来真做分类、要两个传感器合判时，再另函提。原文保留。
- **2.2** 候选采集点**只列本设备下的点**（仅缩小下拉范围，不做识别）。

### 第 3 步　填参数
- **3.1** 「轴向是哪一轴」「速度口径是否有效值」**填在诊断上**（分别随传感器安装与传感器型号走）。
- **3.2** 取数节拍（间隔、窗长）**给默认值（均 60 秒），允许修改**。
- **3.3** 「速度口径是否有效值」旁加提示：「国标按 10–1000 Hz（<600 r/min 为 2–1000 Hz）有效值，请核对传感器/采集器口径」。**不设频带参数**——值是实时库里算好的，频带我方定不了。（2026-09-18，R2）

### 第 4 步　保存生效
- **4.1** 必选采集点没配齐**允许保存**，界面显示缺哪几项，结论带「配置不全」质量码。
- **4.2** **保存即启用**，另给停用按钮。

### 第 5 步　采基线
- **5.1** 简化为：**选一段正常运行时间 → 点「采集基线」→ 完成后自动启用**；标注、建训练集由后台自动做。
- **5.2** 基线**先不做自动更新**，漂移严重时由用户手动重采。

### 由此带来的变化

1. **模块 1 与模块 2 在界面上是两个选项**。现有代码里二者合在一个 `.py`（`vibration_lowfreq`）⇒ 需要拆成两个模块，或同一模块报两个选项；**怎么拆未定，代码暂不动**。
2. 同一台设备可以同时配「经典算法振动诊断」和「AI 模型自训振动诊断」，二者各自选采集点。第 2.1 步的「第二测点」对二者都适用。
3. 第 5 步「采基线」只对「AI 模型自训振动诊断」适用；「经典算法振动诊断」保存即出结论。
4. 此前讨论过的「振动状态监测 / 振动频谱诊断」两个名字作废。
5. 图像识别类（安全帽、表计读数、OCR）**不在设备配置里**，挂在哪里未定。

## 模块 1、2 拆分（2026-09-17 用户定）

**拆成两个独立模块**，各自一个 `.py`。

理由：当初合在一起只为「共用输入、参数不填两遍」；现在设备参数改填在设备上，界面又分设两个选项，这条理由不再成立。二者算法、是否训练、生效方式、出错表现、后续依赖都不同。

| 模块 | 结论点 |
| --- | --- |
| 模块 1 经典算法振动诊断 | 速度最大值、最大值所在轴、ISO 烈度区（文字/数值）、距下一档余量、轴向/径向比、方向性倾向、判据摘要 |
| 模块 2 AI 模型自训振动诊断 | 速度偏离、三轴比例漂移、温升、异常分、判据摘要 |

代价：现场在跑的配置与基线（工件 id=3）挂在 `vibration_lowfreq` 名下，拆分后基线归模块 2 重采（10 段数据）。代码实现与现场部署另行安排。

## 模块 1、2 的内容（2026-09-17 用户按我方建议定）

### 模块 1 经典算法振动诊断
- **1.1** 机器分组**只留第 1、2 组与「不适用」**；填「不适用」则不出烈度分级。（2026-09-18 依据由 ISO 20816-3:2022 改为 GB/T 6075.3-2011，分组定义两者相同。）
- **1.2** 设备额定转速 < 600 r/min：照常出分级，判据摘要注明「低速设备，标准要求另看位移，本结果仅供参考」。
- **1.3** 方向性倾向**保留，界面显示为「提示」**，不作结论（单测点实测 0.767，基线 0.607）。
- **1.4** 报警防抖（连续 N 次超限才算）**先不做**，现场出现跳动再加。

### 1.5 判级改依国标，并对泵判级（2026-09-18 用户定，答 `C-43`）
- 工业机器：GB/T 6075.3-2011（等同 ISO 10816-3:2009），参数 机器分组 + 支承方式，限值与原先两组四格相同。
- ~~**适用范围不由模块判**（15 000 r/min、50 MW 等）：由 AICloud 设备模型把越界设备置为「不适用」，模块见「不适用」即不出分级。~~ ★**2026-10-12 作废**：用户定「不适用应由你判定」，见 §1.5.3。
- 泵：GB/T 6075.7-2015（等同 ISO 10816-7:2009），参数 **泵类别（第Ⅰ/Ⅱ类）+ 额定功率**，按 200 kW 分档（≤200 归小档）；**不看支承方式、不限转速、不加低速注释**。
- 泵限值暂取 Europump 2013 对 ISO 10816-7 的摘录（二手；★2026-10-12 已按 ISO 10816-7:2009 / GB/T 6075.7-2015 原文核对一致，见 `ISO20816-3机组分类与限值.md §7`）：第Ⅰ类 ≤200 kW 2.5/4.0/6.6、>200 kW 3.5/5.0/7.6；第Ⅱ类 ≤200 kW 3.2/5.1/8.5、>200 kW 4.2/6.1/9.5（mm/s 有效值，A/B、B/C、C/D）。
- 同时填了有效的泵类别与机器分组 ⇒ **参数自相矛盾**，落 `CONFIG_INCOMPLETE`，不猜。
- 界面显示名「ISO 区」改为「烈度区」。
- ★（2026-10-12 补注）上面「泵不限转速」与原文不符：GB/T 6075.7 §3.1 / 表 A.2 要求 < 600 r/min 的泵另测峰峰值位移（0.5/1/2 倍工频滤波值）。已按 §1.5.2 改为照判并警示。

### 1.5.1 传感器口径惯例（2026-10-12 用户定）
- 用户原话：「**速度是 RMS、位移是峰峰值，这是业内最常见的组合 —— 以此为惯例！**」
- 落法：参数 `vel_is_rms`（速度口径）取值键不变，显示改为「是：有效值（手册未注明的按惯例视为有效值）」/「否：手册明写为峰值或峰峰值」。
  ⇒ **手册没写口径的传感器照常出烈度分级**；只有手册明写峰值 / 峰峰值才不出。
- 依据：手册写明口径的仁科、博感都是这一组合（`doc/传感器资料/README.md`）；国标判区用的正是速度有效值。
- 位移按峰峰值读：现行判级不用位移（自训偏离是相对量，不受口径影响）；将来接 GB/T 6075.3 位移判据（表 A.1/A.2 为**有效值**）时须换算，接 GB/T 6075.7 表 A.2（**峰峰值**）则同口径。
- 惯例只是缺省假设：现场 SVT10（郎汉德贴牌）口径厂家与客服都答不出，仍建议用标明有效值的测振笔对比一次。

### 1.5.2 按标准判级，无标准的警示（2026-10-12 用户定）
- 用户原话：「**你这边要根据标准判级，没标准的，要有警示信息**」；分情况处理按我方建议执行（用户答「做」）。
- **不在标准范围 ⇒ 不出烈度区，只给数值，判据摘要以「⚠无适用的现场判级标准」开头说明原因**：
  机器分组「不适用」；工业机器额定功率 ≤ 15 kW 或 > 50 MW、额定转速不在 120~15 000 r/min（填了才核）；泵额定功率 ≤ 1 kW（GB/T 6075.7 表 A.1）；只有轴向有读数。
- **判区只取径向两轴**（GB/T 6075.3 §5.2.3/§5.2.4、GB/T 6075.7 §5.3）：轴向读数不参与判区（推力轴承除外，本模块不分轴承类型，一律只取径向）；
  「速度最大值」仍是三轴最大；没填「轴向是哪一轴」时按三轴最大判并警示。采基线时的国标核查同样只看径向。
- **低速（< 600 r/min）照常按速度出分级，警示「标准要求另看位移，本模块只按速度，可能判轻」**：工业机器与泵都加（取代 §1.5「泵不限转速、不加低速注释」）。
- 风机（≤ 300 kW 应依 ISO 14694）、往复机等**暂不单列判据**（用户：「还有很多类别的，比如往复机」）；我方给无标准警示。
  ~~由平台置「不适用」~~（10-12 改由我方判，§1.5.3）；设备类型**要靠平台台账传来**（AI-96）。
- 警示一律写进「判据摘要」，不新增结论点（现场授权数据点已满额）。

### 1.5.3 适用与否由本模块判，平台只传事实（2026-10-12 用户定）
- 用户原话：「**不适用应由你判定**」；方案按我方建议（用户答「按你意见」）。取代 §1.5「适用范围不由模块判」，订正 AI-95 §3 第 2 问。
- **平台传事实**（`machine` 层级）：设备类型（新增 `machineType`，键名取值待 AICloud 台账定）、额定功率、额定转速、支承方式、泵类别。
  ★10-13 `machineType` 作废，改为 ISO 14224 类别 + 型式及联接设备，见 §1.5.5。
- **我方判**（`_grading`，按序）：泵 → GB/T 6075.7（≤ 1 kW 不适用）；往复式机器、螺杆压缩机、水电机组、风电机组 → 不适用（写明另依何标准）；
  燃机 > 3 MW → 不适用（6075.4）；风机 ≤ 300 kW 且柔性支承 → 不适用（ISO 14694）；功率 ≤ 15 kW 或 > 50 MW、转速不在 120~15 000 r/min → 不适用；其余按 GB/T 6075.3。
- **分组由额定功率推出**（> 300 kW 第 1 组，15~300 kW 第 2 组，§4.2）。电动机 / 发电机可按轴中心高分组 ⇒ 平台填了分组以所填为准；
  其他设备填了分组即与功率核对，不一致按参数矛盾不出分级。平台所填「不适用」不再采用（判据摘要注明）。
  ★10-14 `machineGroup` 整个作废、电机改收轴中心高，见 §1.5.6。
- **过渡**：设备类型未传 ⇒ 照判并警示「未能核对是否在标准范围」；额定功率未传 ⇒ 分组按平台所填并警示，平台也没填分组则不出分级。

### 1.5.4 无标准时阈值可配置（2026-10-12 用户定）
- 用户原话：「**除了有国际标准的，阈值应该能配置**」。
- 诊断上新增三条**自定门槛**（`limitAttention` / `limitWarning` / `limitDanger`，速度有效值 mm/s，`position` 层级，无缺省，选填）：预警线、报警线、危险线。
- **只在 §1.5.3 判为「无适用标准」时采用**；有国标的填了也不用（判据摘要注明「有适用国标，自定门槛不采用」）。三条须都填且递增，否则不采用并说明。
- 四段 A/B/C/D 对 **正常 / 注意 / 警告 / 危险**（与国标 B 区算正常不同：自定的第二段就是预警）。判据摘要写「⚠依用户自定门槛（…），非标准」，并保留无标准的原因。
- 采基线的国标核查、只启用自训时借经典出状态，同用这套判据。
- 背景：用户转来一份机器人伺服门槛建议（2.0 / 3.5 / 5.0 mm/s 等，出处不明），我方不写死进代码，改为让用户自填。机器人等变工况设备宜在固定工况下比较（国标限值只适用于稳态）。
- ★**2026-10-13 用户定**：「设置适当缺省值，并说明“≤15 kW 电机可参考 GB/T 41850.1 表 C.1 下端 0.71 / 1.8 / 4.5 mm/s”出处」。落法：
  - **三条都不填**、额定功率 **≤15 kW**（泵即 ≤1 kW）、且**确无专门标准**时，按 GB/T 41850.1-2024（= ISO 20816-1:2016，IDT）附录 C 表 C.1 区界下端 **0.71 / 1.8 / 4.5 mm/s** 判区。

### 1.5.6 机器分组由本模块推出，电机收轴中心高（2026-10-14 用户定，答 C-103）

  只有 H 没有功率 ⇒ 按 H 定组并警示「未核功率范围」；两者都没有 ⇒ 不出分级。非电机不看 H。适用范围仍先按功率核（第 1 章 >15 kW）。
