# 诊断配置流程定案

> 2026-09-17 用户逐项拍板。术语：界面说「设备 / 诊断 / 采集点 / 设备参数」，代码里诊断对应 `Binding`。

## 已定的前提

| 事项 | 结论 |
| --- | --- |
| 实体关系 | 设备是实体；诊断挂在设备下；诊断上记录绑定的采集点 |
| 采集点怎么选 | **用户手工选**，不做自动识别；选错由用户负责 |
| 设备固有属性 | 机组类别、支承方式、额定功率、额定转速等**填在设备上**，按 ISO 20816-3:2022 建模（`AI-45`、`AI-46`） |
| 设备参数改动后 | 界面**提示用户基线失效**；后端不自动停用，由用户决定 |
| 诊断标识 `binding` 取什么 | **未定**（需与 AICloud 协商，暂缓） |

## 五步（振动诊断）

### 第 1 步　在设备上加诊断
- **1.1** 一台设备上**同一种诊断只允许一条**；多测点放进同一条诊断里。
- **1.2** 依赖没装上的模块**不在列表里显示**。

### 第 2 步　选采集点
- **2.1** 振动诊断**支持第二测点**：可选的一组「第二测点 X/Y/Z 速度、温度」，不配即单测点。依据：MAFAULDA 实测三分类两测点比单测点高 18 个百分点。
- **2.2** 候选采集点**只列本设备下的点**（仅缩小下拉范围，不做识别）。

### 第 3 步　填参数
- **3.1** 「轴向是哪一轴」「速度口径是否有效值」**填在诊断上**（分别随传感器安装与传感器型号走）。
- **3.2** 取数节拍（间隔、窗长）**给默认值（均 60 秒），允许修改**。

### 第 4 步　保存生效
- **4.1** 必选采集点没配齐**允许保存**，界面显示缺哪几项，结论带「配置不全」质量码。
- **4.2** **保存即启用**，另给停用按钮。

### 第 5 步　采基线
- **5.1** 简化为：**选一段正常运行时间 → 点「采集基线」→ 完成后自动启用**；标注、建训练集由后台自动做。
- **5.2** 基线**先不做自动更新**，漂移严重时由用户手动重采。
