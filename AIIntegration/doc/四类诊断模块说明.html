四类诊断模块说明

振动、伺服、压装、变频器 —— 模块编排、应用算法、算法接口、数据流转、界面配置。

AIIntegration（纯后端服务）· 2026-09-18 · 给协作同事（AICloud / daqgate / historystore）

一、一页看懂

AIIntegration 部署在 AISERVER，把各类 AI 诊断统一接进 AICloud。三条规矩贯穿所有模块：

  1. 算法域不知道实时库存在 —— 不碰连接、不碰 id、不碰 VQT。它只回答"给你这段数据，结论是什么"。
  2. 结论必须同时给出值、质量码、时刻（VQT 三元组），在类型层强制，"只填值"写不出来。
  3. 算不出来就落质量码，不许编一个数 —— 也不许什么都不发（下游会读成"这段没数据"，查错方向就反了）。

二、协作方须知六条

不知道就会做错的六件，建议整读；其余章节可按需查阅。

1. 停机时数值类结论不写，界面须凭 run_state 置灰。
点上保留停机前最后一值。不置灰的话，界面会显示成"停机时数值一直不动"。
2. anomaly_score 是 0~100 的排序用分数，不是概率。
请勿按百分比呈现。
3. 振动判级已改依 GB/T 6075.3 / 6075.7。
两侧必须同一依据，否则同一台设备两边算出不同的烈度区。
4. 压装输入形态已改：一次压装 = 一个结构值点。
不再是"三个标量点 + 边界标记点"。压装横轴是位移不是时间。
5. 压装界面须注明「本模型不判：漏装、零件破裂」。
模型只出四类，不写清楚会被当成"这两种情况它判为正常"。
6. 导入外部模型要自述通道顺序、采样率、类别顺序，缺一项拒收。
这几件运行期都不报错，只会给出一个看起来完全正常的错结论。VFD 另需自述归一化方式。

四、逐个模块

4.1 经典算法振动诊断（vibration_iso）

算法取窗口内三轴速度最大值 → 按 GB/T 6075.3（一般机组）或 GB/T 6075.7（泵）查限值表 → 判烈度区 A/B/C/D；另出轴向/径向比与方向性提示。
输入测点 1 的 X/Y/Z 速度（X 必填）+ 温度；可选第二测点同样五路。
参数机器分组、支承方式、泵类别、额定功率、额定转速、速度口径确认、轴向是哪一轴、停机门槛。
结论点vel_max 速度最大值、dominant_axis 最大值所在轴、iso_zone 烈度区、iso_zone_code 烈度区(数值)、iso_margin 距下一档余量、axial_ratio 轴向/径向比、direction_hint 方向性提示、run_state 运行状态、evidence 判据摘要
依赖零第三方依赖（纯 Python 标准库）
判级依据已于 2026-09-18 改依国标（原为 ISO 20816-3）。AICloud 侧设备建模同步改依同一依据 —— 两侧必须同一依据。

4.2 AI 模型自训振动诊断（vibration_baseline）

算法先采一条基线（这台设备正常运行时各通道的中位数与四分位距），之后每拍算偏离：(当前 − 中位数) / (四分位距 / 1.349)。
用中位数而不是均值：基线只有十来帧时，一两个离群值就能把标准差撑大，让之后的真偏离显得不显著。
输入 / 参数同 4.1；参数另有「采基线时认哪个标签算正常」。
结论点vel_z_max 速度偏离、ratio_drift 三轴比例漂移、temp_rise 温升、anomaly_score 异常分、run_state 运行状态、evidence 判据摘要
依赖零第三方依赖
anomaly_score 是 0~100 的排序用分数，不是概率。
没有基线就说没有基线：整组落 model_not_loaded，不拿任何默认值顶。样本少于 5 帧不出基线，采基线当场失败并说清。

4.3 停机判定（模块 1、2 共有）

两个振动模块都有可选参数 stop_threshold 停机门槛（mm/s）：三轴速度最大值低于它 ⇒ 判停机。

  • 停机时不判烈度、不出异常分、采基线时剔除停机帧；
  • 新增结论点 run_state（运行 / 停机 / 未判）；iso_zone_code 停机时写 0；
  • 停机时数值类结论这一拍不写，点上保留停机前最后一值 ⇒ 界面须凭 run_state 置灰；
  • 没有缺省，不填即不判 —— 门槛取决于设备本身，给一个"看起来合理"的数会静默停止诊断。

已以 AI-49 知会 AICloud。

4.4 AI 伺服/机械臂运行监测（servo_health）

算法取 9 路遥测的一段窗口（现场 10 Hz、每 5 秒取最近 20 秒）→ CNN-LSTM → 正常 / 轴承退化 + 概率。
输入位置指令、实际位置、跟随误差、转速、转矩、Iq、电机温度、轴承温度、IGBT 温度 —— 9 路全必填。
参数「模型」：CNN-LSTM / 决策树 / SVM，默认 CNN-LSTM。
结论点verdict 结论、probability 概率、evidence 判据摘要
依赖numpy、onnxruntime
它不是振动诊断 —— 一个振动传感器都不用，全靠驱动器内部寄存器。要接它需要的是驱动器通讯口，与振动那条采集路径完全不同。
机械臂不单独设模块：每个关节配一条本诊断。

4.5 AI 变频器（VFD）运行监测（vfd_health）

算法取 15 路的 60 点窗口（1 Hz、每 10 秒取最近 60 秒）→ TCN 三个输出头。
输入三相输入电压 ×3、三相输出电流 ×3、输出频率、电机输出功率、输出转矩、机柜温度、变压器三相温度 ×3、功率单元 Vdc 均值与极差 —— 15 路全必填。
参数无（单一模型）
六类正常 / 冷却系统退化 / 功率单元异常 / 输出电流不平衡 / 输入电网异常 / 过载·异常负载
结论点fault_type 故障类型、confidence 置信度、severity 当前严重度、severity_30s、severity_60s、severity_120s、evidence
依赖numpy、onnxruntime
未来严重度三条是模型直接给的，不是本服务拿当前值外推的。

4.6 AI 压装机运行监测（未落码）

算法每次压装结束触发一次，CNN-LSTM / SVM → 4 类。
四类正常压装 / 卡滞 / 压装不到位 / 配合间隙异常
界面须注明「本模型不判：漏装、零件破裂」。
输入形态已于 2026-09-18 改变（实时库 H-246）：一次压装 = 一个结构值点（位移、速度、力三条曲线同在一个值里），不再是"三个标量点 + 边界标记点"。理由：压装横轴是位移不是时间，拆成三个标量点等于强行按时间对齐；而一个值 = 一次压装，事件边界自然就有。
特征量（峰值力、RMS…）仍算完写回标量点。依赖的结构值点能力已点亮，但尚未投放到现场，故本模块暂未落码。

五、算法接口

新增一个算法域 = 往 domains/ 丢一个 .py。没有第二步 —— 不改骨架、不改路由、不改前端、不改配置。

class MyDomain(Domain):
    key = "my_domain";  display = "界面上的名字";  version = "1.0.0"

    def declare(self) -> Declaration:
        """我要什么输入、要什么参数、出什么结论。★只描述语义，不写任何 id。"""

    def infer(self, frame) -> list[Finding]:
        """给一帧已经取好、对齐好、带质量码与真实时刻的数据，回结论。"""
  • declare() 的内容原样交给 AICloud，前端据此渲染配置界面 —— 加一个参数不需要前端改代码。
  • infer() 拿到的 frame 里已经有：各路采样序列、台账参数、当前启用的工件（模型/基线）、上一拍的跨帧状态。这些都由骨架准备好，域不碰存储。
  • 结论的形状是 Finding(key, value, quality, t)，四个字段全部必填。t 是该结论所依据的数据的时刻，不是算完的时刻、不是写入的时刻。

六、数据流转

步做什么
① 配置AICloud PutBinding → 骨架记下"这条诊断用哪些点、什么参数、什么节拍"
② 建点骨架 PushEntityConfigs → 实时库：按 declare() 的结论点建点，推全量快照
③ 取数骨架 QueryHistory → 实时库：按节拍取窗口内的采样，带质量码与真实时刻
④ 成帧骨架对齐数据，附上台账参数、当前启用工件、上一拍跨帧状态
⑤ 推理算法域 infer(frame) → [Finding, …]
⑥ 回流骨架 PostVQT → 实时库：写结论点
⑦ 呈现AICloud 从实时库读结论点
  • 只有骨架进程写实时库。重型推理进程（视频等）可用同一张证书只读直连，但不链写接口。
  • 写路径断而复连、或对端换实例 ⇒ 必须重推全量快照。引擎重启后点定义会从实体流里消失，而值照样写得进、健康口照样 ready —— 不重推就不会自愈。
  • 结论点的建立是自动的：域的 declare() 多一条输出，下一拍就自动补建点。
  • 回溯判别（拿历史片段用当前模型重跑一遍）不写回实时库，也不动线上的跨帧状态。

七、界面配置

振动诊断走五步；伺服 / VFD / 压装三类没有第 5 步，改为导入模型工件。

  1. 在设备上加诊断 —— 一台设备同一种诊断只允许一条，多测点放进同一条里；依赖没装上的模块不在列表里显示。
  2. 选采集点 —— 支持第二测点（可选一组「第二测点 X/Y/Z 速度、温度」，不配即单测点）。候选点只列本设备下的点。
  3. 填参数 —— 取数节拍（间隔、窗长）默认均 60 秒、允许修改。
  4. 保存生效 —— 必选采集点没配齐也允许保存，界面显示缺哪几项，结论带「配置不全」质量码；保存即启用，另给停用按钮。
  5. 采基线 —— 只对「AI 模型自训振动诊断」适用：选一段正常运行时间 → 点「采集基线」→ 完成后自动启用。标注与建训练集由后台自动做。

导入模型工件（伺服 / VFD / 压装）

在工件页上传模型 → 校验通过 → 启用。导入时会做严格校验，模型必须自述以下几件，缺任何一项拒收：

要自述缺了会怎样
通道顺序喂错顺序不会报错，只会给出一个自信的错结论
采样率无从核对"这段窗口的疏密对不对得上模型期望的"
类别顺序反了就是把"正常"报成"过载"
归一化方式（仅 VFD）少做一次 z-score 不报错，模型照样吐出像模像样的概率与严重度
这几件的共同点 —— 运行期不会报错，只会给出一个看起来完全正常的错结论。所以只能在导入这一刻挡。
