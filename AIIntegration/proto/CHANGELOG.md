# aiintegration.proto 变更记录

> 规矩：**字段编号只增不改不复用**；废弃用 `reserved`；改契约必须升 `proto_version` 并记在这里，
> 且**改即投分发点并发函**（AI-9 §2.3、C-9 §2.1）—— 不投就会出现"我方以为改了、贵方发版还是旧的"，
> 而且不报错。

## 1.16 —— 2026-10-07

**动机**：AICloud `C-72` 按 `AI-76 §5.1` 实跑采基线，训练必败：一条样本只算一帧，人标一段只得 1 帧，`vibration` 要至少 5 帧（`§2`）；
另查出工作台字符串时刻是不带时区的 UTC、契约没写，平台按本地时间解读差 8 小时（`§3`）。两处都是我方缺陷。

**字段不增不改**，只改语义说明与骨架行为：

| 改动 | 说明 |
| --- | --- |
| 文件头 | ★**时间基准一律 UTC**：`Timestamp` 即 UTC 纪元；字符串时刻（各 `*_at`）是 UTC、`YYYY-MM-DD HH:MM:SS`、不带时区；`meta_json` 与 HTTP 口里的时刻是带时区的 ISO 8601（`+00:00`）。行为未变，原来就是 UTC，只是没写 |
| 11 个 `*_at` 字段 | 逐个注释写明 UTC 与格式：`Annotation`、`Dataset` 的 `created_at` / `updated_at`，样本、片段、工件、报告的 `created_at`，`TrainJob` 的 `created_at` / `started_at` / `finished_at` |
| `StartTraining` | ★**训练时每条样本按该绑定的 `window_sec` 切成多帧**（与在线推理每拍同长），从段首起切，不足一窗的尾巴丢掉、没数据的窗不用。框 N 秒得 ⌊N ÷ window_sec⌋ 帧。一个任务最多 5000 帧，超了任务 `failed`、不先取数 |
| `Artifact.sample_count` | 明确是**样本条数**（契约原义），不是帧数；帧数写在 `training_data` 与 `meta_json` 的 `frame_count` |

**骨架的配套改动**：`trainer.py` 一条样本仍只取一次数（窗口 = 整段），在内存里切帧，不多打实时库；
`TrainJob.message` 报「用 N 帧训练（M 条样本按窗长切出…）」，空窗个数、短于一窗被丢的样本都写明。

**兼容性**：字段与编号不动，老客户端照常解析。训练口径变了：同一训练集现在切出更多帧。
现场 `vibration` 还没有任何工件，不受影响（现有 3 个工件都挂在早已下线的 `vibration_lowfreq` 名下）。

**动机**：★**我方在现场撞出来的一个真缺口，不是设计推演** —— 此前**只有"启用"没有"停用"**。

`ActivateArtifact` 只让**同作用域**（域,种类,对象）的旧件让位。于是**作用域本身建错**的那个件

怎么撞上的：2026-09-16 重训基线时 `StartTraining` 的 `binding` 传了空串，

`artifactcache.for_binding()` 找不到对象专属件时**会回退捡这条全域通用件**，
于是该域**日后任何新绑定，只要自己没训过基线，就会套用另一台机器的基线出第②层结论**，
而本该出现的 `MODEL_NOT_LOADED(-1034)` 不会出现。

| 改动 | 说明 |
| --- | --- |
| `rpc DeactivateArtifact (IdReq) returns (MutateRes)` | 停用一个工件。`ok=true, id=1` 本来是激活的 / `id=0` 本来就没激活；没这个工件 `ok=false` |
| 命令行 `deactivate-artifact --id N --yes` | 与 `activate-artifact` 同规矩，**必须带 `--yes`** |
| 命令行 `list-artifacts` 多显示一列 | 训练数据来源（1.6 的 `data_origin`）—— 空显示**「未声明」**而不是留白 |

★**停用后该对象没有可用工件，结论会落 `-1034`，这是对的**：没有基线就该说没有基线，
不是退回"随便挑一个最新的"。界面上请按"会让该对象停止出第②层结论"提示。

**兼容性**：纯新增一个方法，不动任何字段编号。老客户端不调它即可。

## 1.6 —— 2026-09-16

**动机**：AICloud `C-36 §4` 请求，源头是我方 2026-09-16 训出的第一条基线 ——
那条基线**采自实时库的仿真信号**（`C-35 §4.4`、`AI-37 §4`），而"它是仿真的"当时只记在

字符串一改名就断，而「这条结论是不是拿仿真数据训出来的」恰恰是**要挡在人眼前的判据** ——
与 1.5 给 `origin` / `license` 单立字段是同一个道理。

| 改动 | 说明 |
| --- | --- |
| `Binding.data_origin = 9` | **这组点接的是仿真信号还是现场工况**。`simulated` / `field` / 空；不是封闭枚举，按字符串透传 |
| `Artifact.data_origin = 22` | 训练数据的来源性质。**只读**（我方写）：训练产出按样本快照**取最严**，外部导入按导入时声明 |
| HTTP `POST /artifacts/import/{domain}` | 多一个**可选**字段 `data_origin`（不填 = 未声明） |

**★为什么记在绑定上，而不是记在每条标注上**（2026-09-16 用户裁定）：
**仿真与否是点的性质** —— 绑的那组点接的就是仿真信号源，与人框了哪一段无关。
绑定声明一次，标注/样本/工件自动继承，**人没有机会漏填某一段**。
样本**入集那一刻打快照**（照 `Sample.label` 那条既有规矩）⇒ 日后真机接入、
同一绑定改成 `field`，**不会反写**当初用仿真数据训出来的工件。

**三条语义**（`C-36 §4.2`，两侧议定，改动要发函）：

1. **空 ≠ 现场。** 1.6 之前产出的工件读出来都是空，界面按「未声明」显示、与 `field` 用不同样式，**不许当现场**。
2. **取最严。** 训练集里混了仿真与现场，工件那一格记 `simulated`。混了多少比例照旧写在 `training_data` 里。
3. **不是工件的好坏。** `simulated` 不是"差的工件"，跑链路、做回归都该用它。它只回答一件事：**这条结论能不能用来说现场设备的话。**

**兼容性**：纯增量。老绑定与老工件这一格都是空 = 未声明 —— 按第 1 条处置，**不要在渲染时退回 `field`**。
★**不做自动回填**：按绑定"现在"的取值去回填历史样本，方向是错的 —— 日后绑定改成 `field`，
会把当初用仿真数据训的工件洗成现场。老数据就是未声明，如实显示。

★**一处例外，且只朝严的方向**：样本快照为空、而绑定当前声明 `simulated` 时，训练按 `simulated` 计。
理由：这条兜底**不可能**产出一个假的 `field`（绑定说 `field` 时快照为空仍记未声明），
只可能把"不知道"抬成"仿真"。现役那条基线（工件 id=1、训练集 id=1，样本入集于 1.6 之前）
正是靠这条在重训后拿到 `simulated`，而不必伪造历史快照。
