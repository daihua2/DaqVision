## 1 答 `C-64`

### 1.1 `§2.1` 去掉「第二测点」组：已改

`vibration_iso`、`vibration_baseline` 都升到 **2.0.0**：
- `vibration_iso`：只剩 `x_vel` / `y_vel` / `z_vel`；
- `vibration_baseline`：三轴速度加一路 `temp`。

`dominant_axis` 只取 `x` / `y` / `z`。

贵方问有没有判据**必须同时看两个传感器**。现有两个模块里**没有**：烈度取最大、异常分取最大，平台在设备层「取最差」就合得出来。

唯一的例外在将来。我方第二测点当初的依据，是 MAFAULDA 上**分类器合用两点特征**比单点高 18 个百分点，这一步「取最差」合不出来。但故障分类本就「先不做」，眼下没有损失。真要做的时候再另函提。

### 1.2 `§2.2` `InputSpec.axis`：已加，承诺已在骨架里强制

- `axis = 11`，取值 `x` / `y` / `z` / 空，照 `H-261 §2`。贵方的 `none` 对应我方的空。
- 「同一模块内 `(quantity, axis)` 不重复」：**骨架装载域时强制**，重复即装载失败，不会出现在 `ListDomains` 里。所以贵方按「量 + 轴」对角色，一定对得出唯一一个。

### 1.4 `§2.4` 只改参数的 `PutBinding`

| 问 | 答 |
| --- | --- |
| 会不会重置窗口、推迟下一轮？ | **不会**。节拍按（模块, 绑定）记，存绑定只更新内容，下一拍照常、读到的就是新参数 |
| 会不会让已启用的基线 / 工件失效？ | 工件本身不失效。但有**一项例外**：基线记着采集时的「轴向」，**改了 `axialAxis`，基线的「三轴比例漂移」那一项就作废**。这一项落 `model_not_loaded`，判据摘要写「请重采基线」；速度偏离、温升、异常分照出。其余参数都不影响已采的基线（ISO 的判级参数基线根本不用） |
| 会不会重建或换号结论点？ | **不会**，三元组不变（与 `H-281 §3` 一致） |

⇒ 平台改台账时，**只有改「轴向」**需要提示「这会让 N 条 AI 自训诊断的比例漂移失效，需重采基线」。

★这一条是这次查出的**我方缺陷**：基线记了轴向，推理时却不核。改轴向后比例漂移会拿新轴向的比值去减旧基线，错了也看不出来。1.13 已修，契约 `PutBindingReply` 处加了注。

## 2 答 `C-65`

### 2.1 `§2` 检测状态：接；这一次只有 ISO 出

形状照贵方建议：
- `OutputSpec.role = 9`，取值 `status`，**请认这一格、不认键名**；
- 词表封闭为 `normal` / `attention` / `warning` / `danger` / `stopped`，写在契约注释里；
- `choices` 只列本模块会出的那几档；
- 含 `stopped` 的必为 `literal_stopped`；一个模块至多一条。

以上骨架装载时强制，词表外的取值装不进来。算不出时照常落质量码，**不另造档位**。

**`vibration_iso`**：键 `status`，口径如下。

| 烈度区 / 状态 | 检测状态 |
| --- | --- |
| A、B | `normal` |
| C | `warning` |
| D | `danger` |
| 停机 | `stopped` |
| 烈度分级给不出（参数不全、口径未确认…） | 同落 `config_incomplete`，**不报正常** |

★**B 区对「正常」、不对「注意」**（我方用户 10-05 定）：国标 B 区的含义就是「可长期运行」，标「注意」会让多数健康设备亮色。所以 ISO 不出 `attention`。

**`vibration_baseline`：暂不出。** 异常分怎样算「警告」要一组切档阈值，而我方现有的阈值和合成权重**都没有标定依据**。现在出，等于把一组随手取的数当成告警口径。我方用户 10-05 定：先不出，平台那一列空着（与贵方用户「补上之前空着」一致）。有现场数据可标定时再加，届时新增一个点，原有点号不变。

**伺服、变频器、压装、视觉**：同样暂不出。**模块没有 `role="status"` 的结论 = 本模块暂不出状态**，请显示为空，不要按别的结论推。

### 2.2 `§3` 主要结论：接

`OutputSpec.headline = 10`，按声明顺序显示：
- ISO：`vel_max`、`dominant_axis`、`iso_zone`；
- 基线：`vel_z_max`、`anomaly_score`。

### 2.3 `§4`「基线」一列：请改用 `requires_artifacts`

**1. 不能拿 `train` 推。** 伺服、变频器、压装、视觉都**没有** `train`，却**必须导入模型**才出结论；按 `train` 推会把它们显示成「不需要」。

⇒ 1.13 新增 **`DomainInfo.requires_artifacts = 8`**：没有启用中的这几类工件，本模块就有结论出不来。

| 模块 | `requires_artifacts` | 「基线 / 模型」列宜显示 |
| --- | --- | --- |
| `vibration_iso` | 空 | 不需要（保存即出） |
| `vibration_baseline` | `baseline` | 未采 / 正在使用 |
| `servo_health`、`vfd_health`、`press_fit`、`vision_helmet` | `model` | 未导入 / 正在使用 |

★这条由用例钉住：凡接受外部导入模型的模块都必须声明 `model`，凡能采基线的都必须声明 `baseline`。

**2. 实际生效的是哪一件**：**本绑定专用的优先，没有再用全域通用的**（`binding` 为空），按 `kind` 分别取。已写进契约 `requires_artifacts` 注释。

**3. 基线工件的 `kind`** 固定是 `baseline`，导入的模型是 `model`。仍不是封闭枚举，贵方按显示用即可。
