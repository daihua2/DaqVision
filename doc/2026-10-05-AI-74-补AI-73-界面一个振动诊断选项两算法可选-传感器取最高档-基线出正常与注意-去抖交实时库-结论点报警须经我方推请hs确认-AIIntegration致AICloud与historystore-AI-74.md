## 1 界面：一个「振动诊断」选项（致 AICloud）

我方用户撤销了 9-17 的「两个选项分设」，改为：

- 界面上**只有一个「振动诊断」**，用户对一个振动传感器勾选算法：经典算法、AI 自训，或两者都用。
- 平台据此建**一条或两条绑定**：`vibration_iso` 和 / 或 `vibration_baseline`。**两个模块不合并**，契约、点号、归属链都不变。
- 两条绑定可以用**同一个绑定键**（传感器编号）。点号按（模块, 绑定键, 结论名）三元组走，不会撞。
- 以后加一种或去掉一种算法，就是对那个模块建或删一条绑定，另一条不受影响。
- 「采基线」一步只在勾了 AI 自训时出现。没采之前，经典算法照常出结论，AI 自训那条显示「待采基线」（按 `requires_artifacts` 推，见 `AI-73 §2.3`）。

参数仍只填一次：设备参数、轴向由平台从设备、传感器带入两条绑定（`C-64 §1`）。速度口径、停机门槛两条绑定都要，**宜由界面填一次、同时下发给两条**。

## 2 综合状态（致 AICloud）

- **传感器的综合状态** = 名下各条诊断的检测状态取最高档；**设备的状态** = 名下各传感器取最高档。与 `C-65 §1` 的设备层「取最差」是同一条规则，只是多了传感器这一层。
- 档位高低按契约词表：正常 < 注意 < 警告 < 危险；停机单列。
- 两个模块的分工：

| 模块 | 会出的档 | 依据 |
| --- | --- | --- |
| 经典算法 `vibration_iso` | 正常 / 警告 / 危险 / 停机 | 国标（A、B → 正常，C → 警告，D → 危险） |
| AI 自训 `vibration_baseline` | 正常 / **注意** / 停机 | 偏离自身常态（速度偏离 ≥ 3） |

⇒ **警告、危险只由国标给；「注意」只由自训给。** 绝对值还没超国标、但已经偏离自身常态时亮「注意」，这正是要提前几天看到的那种情况。

## 3 订正 `AI-73 §2.1`：基线模块现在出检测状态

`AI-73 §2.1` 说「`vibration_baseline` 暂不出」，同日改了（`vibration_baseline` **2.1.0**）：

- 新增结论 `status`（`role="status"`），取值 `normal` / `attention` / `stopped`：
  - 速度偏离 ≥ 3 → 注意，否则正常；
  - 停机 → 停机（`literal_stopped`）；
  - 没有基线、或速度偏离算不出 ⇒ 同码落坏，**不报正常**。
- 理由：「注意」是最低一档，判错代价小。警告、危险仍不出，因为本模块的门槛没有标定依据，不该把设备说成危险。
- 只看速度偏离，不看比例漂移与温升：那两项的门槛更没有依据。
- **现役影响**：基线那条绑定多一个结论点（新三元组、新号），原有点号不变。

`proto/CHANGELOG.md` 1.13 条里「`vibration_baseline` 暂不出」一句随之作废，以本函为准；契约字段无变化。

## 4 去抖：交给实时库报警，模块每拍如实写（致 AICloud）

- 模块**不防抖、不记跨拍**，每拍写当拍的状态。历史里留的是真实的每一拍，事后能复盘；去抖时长也不会写死在代码里。
- 去抖用实时库报警的 `OnDelaySec`：条件持续 N 秒才报，期间恢复即撤销，按单调钟计时（能力位 `alarm-debounce-timer`）。
- ★**列表的「检测状态」一列请读报警状态机的当前态**（已去抖、可确认），不要读结论点的当拍值。当拍值在「正常 / 注意」之间偶尔会跳，那是去抖要吃掉的抖动。
- 严重度用实时库现成量表（`AlarmEvent.Severity`，OPC UA 1~1000）：

| 检测状态 | 严重度 |
| --- | --- |
| 注意 `attention` | **Warn 300** |
| 警告 `warning` | **MeAlarm 600** |
| 危险 `danger` | **HiAlarm 800** |
| 正常、停机 | 不报（不命中 ⇒ NR） |
