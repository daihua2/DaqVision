## 1 对贵方（产生方）意味着什么 —— 写法

`H-260` 建议稿里"一帧一个值（`wave` 数组 + `sampleRateHz`）"**作废**。按 `AI-59 §2.1`，产生方照这几条写：

| # | 规则 | 例（三轴振动） |
| --- | --- | --- |
| 1 | **一个采样时刻一条** `VQT`，`StructVal` 里只装这一刻测到的量 | 字段 `x`/`y`/`z`，各一个 `SFT_FLOAT` |
| 2 | **T 是这一条自己的时刻**；不存采样率、不存帧号 | 25.6 kHz 就是每 39.0625 µs 一条 |
| 3 | 存**换算后的物理量**，单位写在结构描述的 `unit` 里 | 维特 i16 原码 × 2⁻¹¹ g，f32 无舍入 |
| 4 | 某一路缺了 ⇒ **整条置坏 Q**，绝不以 0 / NaN 代替"没测" | —— |
| 5 | 采样率不同的量（如转速）**另建点**，不塞进同一条 | —— |
| 6 | 字段集不同就分结构；字段名按传感器定（**由采集侧定义并注册**） | 双通道传感器另立一个结构 |
| 7 | 一次压装的起止由一个**标量开关点**给 | 细节 AIIntegration 另函致贵方（`AI-59` 原话） |

**批**：一次 `PostVQT` 带一批（维特一次读回 1024 条就发 1024 条）。上限仍是 **4 MB ≈ 9 万条**，超了整批拒、不截断。

## 2 配置 —— 结构描述与点的 `Paras`

### 2.1 结构描述：每个字段带**物理映射描述**（`AI-59 §4.1`，我方 `H-261 §2`）

采集侧注册结构时，每个字段除 `unit` 外，在 `attrs` 里填两个**约定键**：

| 键 | 取值 | 备注 |
| --- | --- | --- |
| `quantity` | `acceleration` / `velocity` / `displacement` / `force` / `temperature`（首批） | 取值表由**贵方与 AIIntegration 议定**；hs 不校验、原样存取 |
| `axis` | `x` / `y` / `z`（传感器自身坐标系） | 无方向的量**不填这个键** |

- 契约**不改**（`attrs` 早就是自由键值表）。`GetStruct` 的 `def` 原样带回；**导出的 descriptor 不带 `attrs`**，以 `def` 为准。
- ★改 `attrs` 也算改描述 ⇒ **发新版本**（须 `allowNewVersion`）。启动时自动注册仍幂等：描述不变就不出新版本。

### 2.2 点的 `Paras`：结构值点共四个键

| 键 | 值 | 规则 |
| --- | --- | --- |
| `Acc` | `36`（`VT_RECORD`） | 既有（`D-242 §1.3`） |
| `StructRef` | 结构名 | 既有：绑定后不许换绑 |
| ★`ProcChain` | 处理链，自由串：`raw` / `demean,bandpass:10-1000` … | **新**：首次非空即落定；缺键/空串沿用；★之后改了 ⇒ 该点写入**整批拒** + 降级项 |
| ★`TsSource` | **只收** `measured` / `generated` | **新**：同上；其它值（含大小写不符）整批拒 —— 它会被永久落定，拼错只能新建点 |

`TsSource` 的意思（`AI-59 §3`）：`measured` = 每条 T 是测到的；`generated` = T 由采集侧按采样率**生成**（维特 `RAWFIFO` 帧里没有时刻，就是这种）
⇒ 块内丢样查不出，消费方要知道这一点。

★**为什么锁死**：hs 的 `Paras` 只留最新一份原串、**没有变更时刻**。口径中途一改，同一个点前后两段数据含义不同，消费方无从知道从哪一刻起变的。
`AI-59` 提议"一变即新建点"，用户裁定由 hs **强制**（与 `StructRef` 不许换绑同一机制）。
⇒ ★**请贵方组态界面**：这两个键在点**首次写入后**请按只读处理，或至少提示"改了要新建点"——否则用户改完只会看到"写入被拒"。

### 2.3 能力位（写之前探）

| 位 | 担保 |
| --- | --- |
| `struct-registry` / `struct-value` | 既有 |
| ★`struct-stream-attrs` | 这台会锁 `ProcChain`/`TsSource`。★老引擎**不认识**这两个键、照收不误，只有探这一位才分得清 |
| ★`struct-columnar` | 这台写的结构值块可能是 `'S'` 编码 —— 见 §3.2 的降级下限 |

## 3 托管方要知道的两件

### 3.1 WAL 上限与高频结构值源

每条样本都先过 WAL。托管若配了较小的 `HS_WAL_MAX_MB`（e52c 的 drop-in 是 32），WAL 写满会触发**全量封块**，
而全量封块会把**所有标量点**正开着的块一起封掉 —— 结构值源越密，标量块被切得越碎。

按线上每条 44 字节**估算**：一个传感器平均 256 条/秒 ≈ 11 KB/s，32 MB 约 **50 分钟**写满一次；
若有传感器**连续** 25.6 kHz 采集，约 **28 秒**一次。⇒ 接入连续高频源前，请把 `HS_WAL_MAX_MB` 一并调大（量级按源的总速率 × 期望的封块间隔）。
平均节奏下现配置可以不动。

### 3.2 ★降级下限：`1.9.493`

有 `struct-columnar` 的引擎写下的结构值块，**更早的版本解不出**。它们不会丢：`1.9.453` 起压实对"CRC 完好但解不出"的块原样保留，
只是查不到；再升级回来即可见。现场目前**没有任何结构值数据**，所以这一条今天没有实际代价 —— 但结构值源接进来之后，
回滚到 `1.9.493` 以前的二进制，结构值历史会"看起来没了"。

## 4 认领一条：结构绑定的拒收消息报的是存储 id

本轮真 daemon 实测（受限连接、真 id 映射）逮到：**`StructRef` 换绑被拒、未绑定、结构 id 不符**这几条拒收消息，
报的是**存储 id**（全局号），不是推点方自己的 localId。与 `1.9.472` 媒体闸那一条**同一个坑**，当时只修了媒体那一处。

- 贵方 `D-252` 端到端 9 项没撞到它，是因为那轮走回环、两个 id 空间恒等 —— **不是贵方验漏了**；
- `1.9.493` 起 `PostVQT` 里结构值相关的拒收消息**一律报调用方用的那个号**；实测脚本已加断言（"报错里的点号是调用方自己的号"）。
