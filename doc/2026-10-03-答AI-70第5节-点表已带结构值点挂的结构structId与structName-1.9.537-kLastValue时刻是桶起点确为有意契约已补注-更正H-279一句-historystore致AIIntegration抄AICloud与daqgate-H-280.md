## 2. §5.1:点表里的结构

| 项 | 定案 |
| --- | --- |
| 字段 | `int32 structId = 26`、`string structName = 27` |
| 取值顺序 | ① 该点**已绑定** ⇒ 给绑定的结构。即使组态里的 `StructRef` 后来改成了别的名字(换绑会被拒),这里仍给原绑定,因为盘上数据是按它写的。② **还没写过值** ⇒ 按 `Paras` 的 `StructRef` 去注册表查;首次写入时正是按它绑定。③ 非结构值点、没配 `StructRef`、名字在注册表里查不到 ⇒ `0` 和空串 |
| 判读 | `valueType == 36` 而 `structId == 0`,说明这个结构值点没配好结构(写入会被拒,原因见 `GetServerStatus` 的降级项) |
| 版本 | **不给版本**。绑定只锁结构,不锁版本;版本随每条值走(`VQT.StructVal`)。要列字段,用 `GetStruct(id = structId, version = 0)` 取最新版。★解老值时必须用值里自带的版本,不要拿最新版去解 |
| id 空间 | 结构 id 是全库共享的命名空间,受限连接和全量连接看到的是同一个号,不做 localId 翻译 |
| 何时变 | 和其他字段一样:点表流每个周期比对整条 `StoredPoint`,有变化就推一条增量帧。所以"结构比点晚建好"和"首次写入落定绑定"都会如实推出来(用例已覆盖) |
| 能力位 | **`storedpoints-struct-ref`**。★必须先探:老引擎这两格恒为 `0`/空,和"这个点没配好结构"看起来一模一样,两种情况的处理却相反 —— 前者应退回读值的绕法,后者应去改组态 |

有了这两格,AI-70 §1 里"近 7 天没有值就认不出结构"那种情况可以消除:先看 `structId`,再用 `GetStruct` 取字段。`DescribeStructPoint` 要不要改走这条路,由贵方决定;老引擎上仍需保留读值的绕法。

## 3. §5.2:`kLastValue` 的时刻

**是有意的。** 分桶查询的契约是"在网格上提 N 个问题,回 N 个回答",每个回答的时间戳就是它所答的那个桶的起点。代码核对结果:

- 数值路径:`kFirstValue`/`kLastValue` 的值取桶内首笔、末笔好样本,时间戳打在桶起点。
- 离散路径和结构值路径:同上。结构值点的桶里没有真样本时,发 `-1036`,不做保持。

时间戳取样本自身时刻的,只有**发生时刻族**(`kTrendData`/`kMinTime`/`kMaxTime`/`kFirstTime`/`kLastTime`)和 `kRawData`。要样本自身的时刻,请用 `kFirstTime`/`kLastTime`。贵方已改用 `kLastTime`,做法正确。

原来的契约注释只正面列了发生时刻族,没有反过来写明"其余各法的时间戳是桶起点"。按贵方建议,已在 `historystore.proto` 分桶输出契约那一节补上这一句。纯注释,行为没有变。
