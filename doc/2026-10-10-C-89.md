# C-89 请求：授权拒绝原话里的「本次新增」统一写实际加进去的个数（被拒即 0），标点同平台；网关界面同口径

## 0 一句话

- 我方用户 10-10 定：授权拒绝原话里的「本次新增」，一律写**这次实际加进去的个数**。被拒就是一个没加，写 **0**。想加几个只记在日志里。
- 起因：用户在平台上看到「本次新增 3」，读成了「已经加进去 3 个」。平台的原话 10-10 已改成「本次新增 0」（V1.0.730 起）。
- 实时库预检的原话现在写的是**想加的个数**（如「本次新增 19」）。AI-91 起，它会经 AI 服务原样显示在平台界面上，和平台自己的原话并排出现，同一个词两种意思。请改成同一口径（`§1`）。
- 网关界面上的同类提示请同样处理（`§2`）。

## 1 请 hs 改

`CheckPointQuota` 回 `Deny` 时的原话：

| 情形 | 现在（1.9.555） | 请改为 |
| --- | --- | --- |
| 已满额 | `已达授权数据点数(已用 2193 / 授权 2193,本次新增 19),请购买授权后再添加数据点` | `已达授权数据点数（已用 2193 / 授权 2193，本次新增 0），请购买授权后再添加数据点` |
| 不许新增（`-1`） | `未授权,不能新增数据点(已用 280,本次新增 1),请导入授权后再添加数据点` | `未授权，不能新增数据点（已用 280，本次新增 0），请导入授权后再添加数据点` |

- 「已满额」那句改完后与平台原话**逐字相同**（`docs/44 §22.15`）。
- 标点请用全角（，（）），与平台原话一致。两边的原话会出现在同一个界面上。
- 想加的个数（19、1）请照旧记进贵方日志，不要放进原话。
- 状态口降级项、日志里的说法（如「拒收 N 个新存储点」「已拒收新点 N 次」）讲的是被拒的个数，不是这个词，**不用改**。
- `CheckPointQuotaRes` 里的数字字段不变。本函只请改给人看的那句话。
