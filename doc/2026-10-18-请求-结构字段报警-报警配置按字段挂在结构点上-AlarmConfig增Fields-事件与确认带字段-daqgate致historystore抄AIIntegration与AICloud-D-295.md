# D-295 请求：结构字段报警 —— 报警配置按字段挂在结构点上，事件与确认带字段

**涉**：`EntityConfig.Alarm`（14）、`AlarmConfig`、`AlarmEvent`、`AlarmAckItem`、`ActivePointAlarm`、`AlarmQueryReq`；`H-299`（按字段取）；`D-294`（待答）

## 0 一句话

- 用户 10-18 定：结构值点要能**按字段**配报警，报警仍在实时库求值。
- 做法：在结构点自己的 `AlarmConfig` 里加一组按字段的配置，**不为字段派生独立的点**。不占全局号、不计数据点授权、不增加存储。
- 请贵方：
  - 求值时拆出配了报警的字段（`H-299` 按字段取已有拆字段能力）；
  - 报警身份、事件、确认、活动报警、查询各带上字段。
- 点级报警的行为、身份算法全部不变，存量条件不断链。

## 1 为什么这样做

| 做法 | 结论 |
|---|---|
| 甲：每个字段派生一个独立标量点，报警照普通点配 | 不取。VBST1 一个点就有 13 个字段，多台设备点数翻十几倍；占全局号、计入授权（AISERVER 已用 2195/2193）；与我方「字段不是独立的点」的定案相反 |
| **乙：报警配置按字段挂在结构点上** | **采用** |
| 丙：在结构定义上配 | 不取。结构定义的版本发布后不可改，阈值一改就要出新版本；阈值也因设备而异 |

结构值里的字段值已是**工程值**：网关按系数换算后写入，例如 Modbus 字段 = 原值 × 系数。字段报警的限值、死区、状态区间因此用字段的工程单位，与点级「求值在转换之后、一律工程值」的口径一致。

## 2 提议

### 2.1 配置：`daqcontract.proto`

```proto
// 结构点上一个字段的报警。限值 / 状态的语义与点级 LimitAlarm / StateAlarm 逐字相同
// (单向滞回死区、时间去抖、ExceptionItem、开关量只许 1 行状态行 …… 全部照搬)。
message FieldAlarm
{
	string				Field	= 1;	// 结构定义里的字段名。按名对,不按序号 —— 改版插字段不错位
	optional LimitAlarm	Limit	= 2;
	optional StateAlarm	State	= 3;
}

message AlarmConfig
{
	optional LimitAlarm	Limit	= 1;
	optional StateAlarm	State	= 2;
	repeated FieldAlarm	Fields	= 3;	// 仅结构值点(valueType 36)有效
}
```

规则（违反的一律按**配置错误**显形，即 `StateItem = "NC"` 的事件，与现有口径相同，不静默跳过）：
1. 结构点只用 `Fields`；结构点上的点级 `Limit` / `State` 判配置错误，因为一条结构值没有可比的单值。非结构点上的 `Fields` 同样判配置错误。
2. 同一字段只能出现一次；同一字段同时给 `Limit` 和 `State`，按点级同一条规则判配置错误、不求值。
3. 字段类型：
   - 限值只能配数值字段；
   - 状态表能配任何标量字段（数值、布尔、字符串、时间戳）；
   - 数组、字节串、数值缓冲判配置错误。
4. **字段对不上**：按每条值所携带的 `StructVersion` 解析字段名。该版本里没有这个字段，或类型变得不可比，这一条判配置错误。按条件只报一次，配置或版本变化后重置，避免自身成为风暴源。

### 2.2 求值

- 结构值入库时，只拆配了报警的字段，逐个按点级同一套逻辑求值：限值、状态、死区、去抖（单调钟定时、`OccurNs` 取条件成立时刻）。
- 质量：一条结构值只有一个质量，各字段共用。坏值按标量点的同一口径处理。
- `AbnormalValue` / `ResumeValue` 填**字段值**。
- 补录 / 回放路径与点级相同（按采样时间推进）。

### 2.3 身份与事件：`alarm.proto`

| 消息 | 新增 | 说明 |
|---|---|---|
| `AlarmEvent` | `string Field`；`string FieldDes` | 点级报警为空串。`FieldDes` 是字段显示名的**快照**，取求值时的结构定义，与 `TagDes` 同理：事后结构改名不改历史 |
| `ConditionId` | 字段报警为 `hash(TagId, Kind, Field)` | **`Field` 为空时与现有算法逐位相同**，存量条件与活动报警不断链 |
| `AlarmAckItem` | `string Field` | 确认按 (TagId, Kind, Field, StateItem) 定位；空 = 点级 |
| `ActivePointAlarm` | `string Field` | 点报警状态流里每条活动报警带上字段，我方点表据此在字段子行上标出报警 |
| `AlarmQueryReq` | `string Field` | 与 `TagId` 合用的过滤；空 = 不按字段过滤 |

**不变**（仍按点归集）：
- `ListAlarmedPoints`：任一字段在报警，即算该点在报警；
- `SubscribeNormalPoints`；
- `MonitorAlarmStats` 的分组。

计数按条件数：一个点上三个字段在报警记 3 条，与现有「同一点限值 + 状态记 2 条」同口径。

### 2.4 能力位

建议 `alarm-struct-field`。缺位时，我方组态界面不开放字段报警的编辑，只提示需升级实时库。
