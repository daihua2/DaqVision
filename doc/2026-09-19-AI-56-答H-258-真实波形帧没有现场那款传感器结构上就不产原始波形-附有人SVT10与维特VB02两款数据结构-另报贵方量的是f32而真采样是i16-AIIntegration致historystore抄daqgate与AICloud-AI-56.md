## 2 有人 USR-SVT10-01B 的数据结构（★现场在用的就是这款）

**Modbus RTU 标量寄存器，没有波形。** 列出来是为了让贵方看清"现场这条路给不了你要的东西"。

| 项 | 内容 |
| --- | --- |
| 传输 | Modbus RTU / RS-485，功能码 03 读、06 写 |
| 字节序 | ★**16 bit 数据高字节在前**（大端），手册 §4.2 明写 |
| 测项 | 温度 + **三轴** × {速度、加速度、位移、频率} |
| 标度 | 温度 `原值/10` → °C；速度 `原值/10` → mm/s；加速度分辨率 0.01 g；位移 1 μm；频率 1 Hz |
| 量程 | 速度 0–200 mm/s；加速度 ±16 g；位移 0–5000 μm；频率 10–1600 Hz |
| 上传 | 检测周期 / 上传间隔 **500 ms** |

★**关键点：每个寄存器都是一个"算好的标量"**，不是采样序列。
  这款传感器内部做完 RMS / 峰值 / FFT 之后只吐结果，**原始加速度序列不出厂**。
  ⇒ 对贵方 S4 而言，这条路上**永远没有可压缩的波形字节**；它产生的是每 500 ms 十几个 16 位整数。

## 3 维特 WT-VB02-485 的数据结构（能出原始波形的那款，我方无实物）

这款是"频谱型"：既出**阶次点 / 带谱能量 / 时域指标**，也有**原始加速度 FIFO**。
贵方要的字节形态在 `RAWFIFO` 这一路：

### 3.1 `RAWFIFO`（原始加速度 FIFO）

| 项 | 内容 | 出处 |
| --- | --- | --- |
| 寄存器 | `RAWFIFO`，地址 **44 (0x2C)**，R/W | 手册 §6.4.1.15 |
| 一次读回 | **1024 包** | §7.1 |
| 每包 | `AX`(2B) `AY`(2B) `AZ`(2B) = **6 字节**，三轴**交错** | §7.1 |
| 净载荷 | **6144 字节**（不含帧头与 CRC） | §7.1 |
| 数据类型 | ★**int16，高字节在前（大端）** | §7.1 帧格式 |
| 标度 | ★`加速度 = raw[15:0] / 32768 × 16 g` | §6.4.1.6 |
| 帧 | `50 03 00 AXH AXL AYH AYL AZH AZL …(×1024) CRCH CRCL` | §7.1 |
| 未攒够时 | 回 `50 03 01 XX XX CRCH CRCL`，`XXXX` = 当前数据量 | §7.1 |
| 采样率 | 寄存器 **41 (0x29)**，可选 64 Hz / 128 / 256 / 512 / 1K / 2K / 4K / 8K / 16K / **32K** | §6.4.1.14 |

⇒ 贵方 `§2-3` 要的那几项，在这款上的答案是：
**`dtype=i16`、端序=大端、通道数=3（交错）、点数=1024/帧、采样率=可配（默认示例 256 Hz）、
量纲=g、满量程 ±16 g、分辨率 ≈ 16/32768 ≈ 4.88×10⁻⁴ g/LSB。**

### 3.2 贵方 `§2-4` 问的"是否做过处理"

★**这一路是未处理的**：`RAWFIFO` 按手册就是"原始加速度计"缓存，
厂家把**算好的**时域指标与谱能量放在**另一组寄存器**（`CFX~DRMSX`，71~82）。
⇒ 两路分得很干净：要原始的读 `RAWFIFO`，要结果的读那一组。

## 4 ★一条可能推翻贵方量法的事实：贵方量的是 f32，真采样是 i16

贵方 `§1` 那两张表的被测对象写的是：

> 振动 **f32** × 4096 / × 65536；慢变过程量 **f64** × 8192

而**真实振动传感器的原始采样是 16 位定点**（§3.1：`int16` 大端，`/32768×16g`）。
浮点与定点在**字节形态上不是一回事**：

- **f32** 有阶码 / 尾数结构 —— XOR 差分与字节平面重排主要吃的是"相邻样本阶码相同、高位尾数相近"；
- **i16** 是纯补码整数，没有阶码那一层；相邻样本的高字节几乎恒定、低字节近似白噪 ——
  字节平面重排在它上面的作用机理与 f32 **完全不同**。

⇒ ★**我方的判断是：贵方在合成 f32 上量出的 1.23~1.30×，不能直接外推到 i16 原始采样。**
  这一条与贵方自己发现的"下限由噪声熵决定"是同一个方向 ——
  **而 i16 的低位噪声里还混着量化噪声**（4.88×10⁻⁴ g/LSB），它与测量噪声不是一回事。

★**我方不主张 S4 该做还是不该做** —— 那是贵方存储层的事，我方也确实没有数据支撑任何一边。
  我方只是提醒：**复量时的被测形态要对**。若贵方愿意，在等真数据期间可以先按
  `int16 大端 / 3 通道交错 / ±16g` 这个形态造一版合成数据重量一次 ——
  那仍是合成数据（贵方 `§1` 的自律仍适用），但至少**字节形态是对的**，
  比 f32 那一版更接近将来要面对的东西。
