## 2 答问 2：物理映射描述 —— 加，用约定键，契约不改

**选约定键，不做正式字段**。理由：`StructField.attrs` 本来就是自由键值表，已随结构描述**持久化、跨重启、跨版本**；
做成正式字段要改契约、三方各升一次级，而贵方要的只是"各方按同一组键与取值填、原样带出"。

### 2.1 ★键名（我方定，请各方照用）

| 键 | 取值 | 说明 |
| --- | --- | --- |
| `quantity` | 小写英文物理量名，首批：`acceleration` / `velocity` / `displacement` / `force` / `temperature` | 取值表由**产生方与消费方议定**（daqgate 与贵方），hs **不校验、不解释**（定稿 #21 不变） |
| `axis` | `x` / `y` / `z`（传感器自身坐标系） | 无方向的量**不填这个键**（不要填空串） |
| （单位） | —— | 仍走已有的 `StructField.unit`，不进 `attrs` |

贵方 §4.1 的边界我方照录：**只放结构本身的属性**；"这一轴在这台机器上是轴向还是径向"取决于安装，**不进结构描述**。

### 2.2 三条事实（都已验证）

- **取回**：`GetStruct` 的 `def` **原样带回** `attrs`。真 daemon 实测：注册 `x/y/z` 三个 `SFT_FLOAT`、各带 `quantity=acceleration` 与 `axis`，
  `GetStruct` 回来逐项相同（`scripts/live/structrow-live-check.py` [1]）；跨重开的持久化另有单测。
- ★**导出的 descriptor 不带 `attrs`**：protobuf 的 `FileDescriptorProto` 里没有放自由键值的位置（除非定义自定义 option，那等于改契约）。
  ⇒ **物理映射描述以 `GetStruct.def` 为准**。同一次 `GetStruct`（带 `withDescriptor=true`）两样都回，贵方绑定核对时读 `def`、解码时用 descriptor。
- **改 `attrs` = 发新版本**：描述比较把 `attrs` 算在内，只改一个物理量名也会生成新版本（与改字段同一规则，须 `allowNewVersion`）。
  点绑结构 id 不绑版本，贵方按字段名绑定不受影响。

## 3 答问 3：`Paras` 的改动**没有**时刻记录 ⇒ 口径锁死

**直答**：hs 对 `Paras` 只保留**最新一份原串**，不存历史、不记变更时刻。查不到"某时刻起处理链变了"。

⇒ 贵方建议的规则"**处理链或时标来源一变，就新建点**"我方采纳，并由用户裁定在 **hs 侧强制**（与结构绑定 #8 同一机制），
不留成一条靠人记住的约定：

| 项 | 定案 |
| --- | --- |
| 键名 | ★`ProcChain`（处理链，自由串，如 `raw` / `demean,bandpass:10-1000`）、`TsSource`（时标来源） |
| `TsSource` 取值 | **只收** `measured` / `generated`（大小写敏感）。★其它值整批拒 —— 口径会被**永久落定**，拼错一个字母就只能新建点 |
| 首次 | 首次见到**非空**值即落定并持久化（两项各自落定，可以先来一项、后补一项） |
| 缺键 / 空串 | = 沿用已落定的值，**不报错**（组态往返丢键不是"清除"意图，与 `StructRef` 同一条） |
| ★改了 | 来件非空且与已落定的不同 ⇒ **该点写入整批拒**（`FAILED_PRECONDITION`，消息写明原值、来值、"改口径请新建点"）+ 进 `GetServerStatus` 降级项，**只记不清**；两项都不改 |
| 适用 | 结构值点（在写入结构值时校验） |
| 能力位 | `struct-stream-attrs` —— ★老引擎**不认识**这两个键、照收不误，推点方要靠这一位分辨"这台锁没锁口径" |

实测：单测 + 端到端 3 例 + 真 daemon 3 项（改处理链被拒、降级项出现、报错里是**调用方自己的点号**）。

## 4 答问 4：列式编码 —— 已做完、已上写入路径

贵方说"不急于本轮"，但它是逐条形态的前置（记录数上去了、`C-49` 说盘上只剩约 1.5 天），我方本轮做完了。

### 4.1 做法

结构值块多了一种编码 `'S'`，与 gzip **取较小者**，从不因换编码变大：

| 列 | 编码 |
| --- | --- |
| 时刻 | delta-of-delta（与标量的 Gorilla 同一套；等间隔几乎每条 1 bit） |
| 质量码、结构 id/版本 | 游程（一段一份） |
| 值 | 按 protobuf **线格式**拆成"字段 → 列"；float 列在 Gorilla XOR / XOR+字节平面重排+gzip / 重排+gzip 三者中取最小 |
| 锚点等非结构值行 | 整条原样带着，不会因为块里夹一个锚点就整块退回 gzip |

- ★**不读结构注册表**：只按线格式拆。编解码在读路径与压实路径上，不该因为注册表出问题而读不出数据。
- ★**逐字节无损由两道闸保证**：每条拆完重拼须与原字节相同；整块编完**立即解一遍**逐条比对。任一不过 ⇒ 这块照旧 gzip。

### 4.2 数字

| 来源 | 结果 |
| --- | --- |
| 单测（合成三轴振动，i16 × 2⁻¹¹ g 量化，25.6 kHz，一块 1200 条） | 较整块 gzip **再小 33~46%**；未压缩 → `'S'` **5.2~7.0 倍**；**4.0~5.4 字节/条**（噪声 σ 0.05 → 0.0005 g） |
| 真 daemon（三路三轴、38.5 万条/路） | 盘上 331 块中 330 块是 `'S'`（剩一块 48 字节的尾块 gzip 更小，属设计）；**4.65 字节/条**（上界） |

⇒ 按贵方估算的节奏（平均 256 条/秒/传感器）：每传感器 **≈ 1.0~1.4 KB/s，约 90~120 MB/天**（合成数据口径）。

★**都是合成数据**。§6 请贵方给 FEMTO 副本，我方在真实振动上复量。

## 5 答问 5：三件确认

### 5.1 §5.2 结构值不做等值去重，读路径也不吃连续等值 —— ✅ 确认

- **写路径**：结构值点强制逐字档，忽略 `compErr`/`frozenSec`，不做 SDT、不做等值去重（既有，不变）。
- **读路径**：那道去重只折叠 **T（纳秒）+ V + Q 全等**的记录 —— 它存在的原因是开着的块反复落盘留下多代副本。
  **T 不同的两条永远不折叠**，不论值是否相同。
- **实测**：真 daemon 上一帧 2560 条里放 **200 条连续等值**的饱和样本，按时间范围取回 **200 条一条不少**；
  端到端用例另验一批 1024 条里 100 条连续等值，同样一条不少。

### 5.2 §5.3 逐条数组只走 `QueryHistory` —— ✅ 确认，不需特殊处置

- `SubscribeVQTs` 仍是约 200 ms 推一次最新值（`H-244 §8` 不变），**推不出一帧**，至多当触发器。
- **实测线上每条 44 字节** ⇒ 1024~2560 条 ≈ **45~113 KB**，远在 4 MB 缺省接收上限之内。真 daemon 取 2560 条一帧 **25~41 ms**。
- ★**整点大范围取要分段**：实测一次取一路 38.5 万条是 **18 MB**，超过我方建议的 16 MB 接收上限 —— 按 `H-244 §7` 的换算，
  每次 **≤ 约 35 万条**（16 MB ÷ 44 B）；按帧取不会碰到。

### 5.3 §5.4 写入节奏 —— ✅ 单点无速率上限

- **没有单点写入速率上限**。真 daemon 实测（开发机 WSL）：三路三轴、每批 1024 条持续写 **≈ 17 万条/秒**，每批时延 p50 5.8 ms / p99 10.4 ms ——
  是三路 25.6 kHz **连续**采集（7.68 万条/秒）的 2.2 倍，是贵方估算平均节奏的 200 倍以上。
  ★这是开发机的数字；现场机器（尤其 ARM 网关）未量，别直接套。
- 要知道的限制（均为既有，`H-244 §6`）：
  - 单次 `PostVQT` **4 MB** ⇒ 逐条形态约 **9 万条**；超了整批拒，**不截断**。贵方"一次读回 1024 条成批写"远在线内；
  - ★**时间戳早于 2010-01-01 的样本静默丢弃**（整批仍回成功）。`TsSource=generated` 的点 T 是采集侧生成的，请确认生成的基准时刻已校时；
  - 写入校验（结构绑定、口径）已改为**每批每个点做一次**，逐条只比结构 id —— 一批 1024 条同一个点不再是 1024 次查描述。
