## 0 一句话

- 我方用户 10-10 定：主要结论里「烈度区」的值改用彩色 TAG，**A 新投运 绿、B 可长期运行 蓝、C 不宜长期连续运行 橙、D 足以造成损坏 红**。
- 每个取值显示什么颜色，契约里没有地方说。平台若自己认「`iso_zone` 的 A 是绿」，就违反了 `C-65` 立的「只看声明、不认结论名」。所以请贵方在结论声明里给**每个取值标一个显示色调**（`§1`）。
- 色调**只管显示**，不表示严重程度。严重程度照旧由检测状态（`role=status`）说：B 按 GB/T 6075 属于正常，检测状态也判正常，只是显示成蓝色，用来和 A 区分。

## 1 请求：`OutputSpec.choice_tones`

建议（字段名、编号以贵方正本为准）：

```proto
message OutputSpec {
  ...
  // 1.19：取值的显示色调，与 choices 同序。只管显示、不表示严重程度（严重程度看 role=status）。
  //   取值：success | info | warning | error | default；空串等于 default。
  //   整格为空 = 这项结论不上色（平台照旧）。不为空时长度须与 choices 相同。
  repeated string choice_tones = 11;
}
```

烈度区请声明为：

| choices | choice_displays | choice_tones |
| --- | --- | --- |
| A | A 新投运 | success |
| B | B 可长期运行 | info |
| C | C 不宜长期连续运行 | warning |
| D | D 足以造成损坏 | error |
| 停机 | 停机 | default |

- 别的带取值清单的结论（如最大值所在轴、方向性提示）不需要上色，留空即可。
- 色调词跟界面库的四种语义色对应。平台按它取主题里的成功 / 信息 / 警告 / 错误色，跟随明暗主题。`default` 用次要文字色。
- 当前值不在清单里时不上色，原样显示。

## 2 平台怎么用

- 设备列表右栏、AI 诊断列表的「主要结论」：带取值清单的结论，值用线框 TAG，颜色取该值的色调。现在 TAG 一律是主色。
- 整格为空的结论、老版本的模块：照现在的样子显示，不受影响。
- 平台等贵方 1.19 正本到了、同步生成码之后再改界面。在那之前烈度区 TAG 维持主色。
