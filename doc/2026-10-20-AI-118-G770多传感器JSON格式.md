## 0 一句话

- 新款 G770（轻边缘版）可以自己当 Modbus 主站轮询多台 SVT10，再经 MQTT 以**固定结构的 JSON** 上报。~~一台网关一个包，所有从站的点平铺在同一个 `r_data` 数组里~~ 〔2026-11-02 订正〕一轮采到的点按点表顺序**均分成 `EDGERPTNUM`（上报分包数）个包**，设为 1 时才是一轮一包。分包不看从站边界，**一包不等于一台**。每个包里的点平铺在 `r_data` 数组里。组包与分包规则见 **§3.5**。
- **报文里没有从机地址，也没有传感器标识**，只有网关 SN 和点的变量名。哪一点属于哪台传感器，只能靠变量名约定。我方建议用 `aNN_` 前缀，并给每台加一个读地址寄存器的校验点（§5）。
- 下发写入的值**不按倍率反算**，写的是寄存器原值；读回的值是乘过倍率的（§4）。

## 3 上报报文（原文 p.9、p.13–15 §3.1.1–§3.1.2）

### 3.1 结构

```json
{
  "params": {
    "dir": "up",
    "id": "<设备 SN>",
    "sys_sn": "<设备 SN>",
    "sys_imei": "<IMEI>",
    "sys_local_time": "<时间>",
    "r_data": [
      { "name": "<变量名>", "value": "<值>", "err": "0" }
    ],
    "<自定义键>": "<自定义值>"
  }
}
```

### 3.2 字段（原文 p.15 表 3，加 p.9 开关说明）

| 字段 | 原文 | 是否必有 |
| --- | --- | --- |
| `dir` | 「轮询采集上报为 up」 | 必有 |
| `id` | 「信息 ID 号……上报中，默认采用设备 SN 作为 ID」 | 必有 |
| `sys_sn` | 勾「SN 上报开关」才有 | 可选 |
| `sys_imei` | 勾「IMEI 上报开关」才有 | 可选 |
| `sys_local_time` | 勾「时间上报开关」才有，「可选择上报格式为本地字符串或数值型 UNIX 时间戳」。原文图 5 的本地字符串样例为 `"2025-08-01,10:05:04"`，**不带时区** | 可选 |
| `r_data[].name` | 点位名称，即点表里的「变量名」 | 必有 |
| `r_data[].value` | 「点位有效数据」，即按倍率计算后的值。查询错误时为空 | 必有 |
| `r_data[].err` | 「0 表示成功，1 表示从机无响应；2 表示 CRC 校验不通过；其他值表示 Modbus 错误码（如 0x81）」 | 必有 |
| 自定义字段 | 「最多支持 10 条自定义字段。变量名、数值最多支持 60 个字符」，与 `r_data` 平级 | 可选 |

- 手册所有示例中，`value`、`err` 都是字符串（带引号）。
- 点表里的「备注」**不进 JSON**（原文 p.9）。
- 原文图 5 实拍报文（节选）：

```json
{
  "params" : {
    "dir" : "up",
    "id" : "02502025061200006179",
    "sys_sn" : "02502025061200006179",
    "sys_imei" : "861213058429298",
    "sys_local_time" : "2025-08-01,10:05:04",
    "r_data" : [ {
      "name" : "temp1", "value" : "16140", "err" : "0"
    }, {
      "name" : "temp2", "value" : "3", "err" : "0"
    } ],
    "MUN" : "09087",
    "09" : "0897",
    "abd" : "abd"
  }
}
```

### 3.3 每个点的配置项（原文 p.9–10）

变量名、从机地址（1–247）、功能码（01/02/03/04）、寄存器地址（0–65535）、数据类型（位；16 位有/无符号；32 位有/无符号与浮点，各分 ABCD、CDAB 字节序；字符串）、倍率（只做乘法，0.000001–99999999）、上报方式（不上报、直接上报，或变化上报：超过幅值才报）、幅值。点表**最多 150 点**，可用 CSV 导入导出。

全局：周期轮询时间默认 30 s，点间轮询间隔默认 100 ms，轮询超时默认 200 ms。断点续传：断网时最多缓存 500 条，重连后「单包上传 1–50 条」（原文 p.15 §3.1.3）。

### 3.5 组包与分包规则〔2026-11-02 补〕

本节是实测结论，测试条件为：G770 轻边缘版固件 V1.1.03，用模拟从站模拟 3 台 SVT10，详见 `AI-119 §1`、`AI-120 §1`。手册没写分包规则。

#### 3.5.1 规则

| 项 | 规则 | 依据 |
| --- | --- | --- |
| 组包范围 | 一轮轮询的点合起来上报。上报方式为「不上报」的点不进包；选「变化上报」的点，没超过幅值就不出现（§3.3、§5.1） | 手册 |
| 分包数 | 由「上报分包数」`EDGERPTNUM` 决定，一轮出 N 个包 | 实测 N = 1、2、3 |
| 怎么分 | **按点表顺序把点数均分成 N 包**，不看从站边界，同一台的点可能被分到两个包里 | 实测 |
| 包的结构 | 每个包都是 §3.1 的完整结构，`params` 下各带 `dir`、`id`、`sys_sn`、时间字段和 `r_data` | 实测 |
| 包的时间 | 每包各带时间字段，表示**这个包开始采集的时刻**，不是发送时刻。同一轮的几个包时刻不同，16 点一包时相差 2–3 s。时间字段的键名、类型和 8 小时偏差，见 `AI-119 §2` | 实测 |
| 读失败的点 | 仍在包里，只有 `name` 和 `err`，没有 `value` 键 | 实测 |
| 包序号 | 报文里**没有**「本轮第几包」「本轮共几包」这类字段，接收端判断不了一轮的包是否收齐 | 实测 |
| 投递 | 每包是一条独立的 MQTT 消息，QoS 按推送主题的设置；QoS 0 时每包可能单独丢。启用了多个推送主题时，**每个主题各发一份** | 实测 |
| 包大小 | 16 点一包约 835 字节 | 实测 |

#### 3.5.2 实测分包

| `EDGERPTNUM` | 点表 | 实际分包 |
| --- | --- | --- |
| 1 | 42 点（3 台 × 14） | 1 包，42 点 |
| 2 | 42 点 | 21 + 21。第 1 包是 a01 全部加 a02 前 7 点，第 2 包是 a02 后 7 点加 a03 全部，**a02 被切开** |
| 3 | 42 点 | 14 + 14 + 14，恰好一台一包 |
| 3 | 48 点（3 台 × 16，`AI-120 §1.1`） | 16 + 16 + 16，恰好一台一包 |

「一台一包」不是设备按从站分包，只是点数恰好对齐。要同时满足两条：**各台点数相同**，**点表按站连续排列**，且分包数等于台数。接入点数不同的传感器、某台增删点、点表顺序变了，一个包里就会有两台的点。

#### 3.5.3 分包数怎么选（建议）

| | `EDGERPTNUM` = 1 | `EDGERPTNUM` = 台数 |
| --- | --- | --- |
| 流量 | 每轮只有一个包头，3 台时约省 10% | 每台一个包头 |
| 时刻 | 所有台共用一个时刻 | 每台各有自己的时刻 |
| 丢包影响 | 丢一包，这一轮全部缺失 | 丢一包，只缺一台 |

我方测试机现在设的是 3（`AI-120 §1`）。不论设多少，只要按 §3.5.4 写，接收端都不用改。

#### 3.5.4 接收端写法（`AI-120 §2` 约定）

1. **按点名前缀 `aNN_` 把值归到第 NN 台**。不按包归站，也不看点在包里的位置。
2. 每个值的时刻，取它**所在包**的时间字段。不要把同一轮的几个包对齐成同一个时刻。
3. 不依赖包数、每包点数、包内顺序。

#### 3.5.5 断点续传的补发包另算

断网后补发的历史数据**不是**本节的结构，是另一套 `cache_data` 结构。补发包的条数由 `BREAKRPTNUM`（0–50）决定，**按点计**，不按轮。恢复连接后，每轮实时包之后跟 1 个补发包，见 `AI-119 §3.3`。现在定的方案已经关闭断点续传（`AI-120 §1`）。

#### 3.5.6 未测

1. 点数不能被 N 整除时（例如 42 点设 4）怎么分，各台点数不同时怎么分。推测仍按点表顺序均分，余数落在哪个包未知。按 §3.5.4 写，接收端不受影响。
2. 自定义字段（§3.2）在分包时是否每包都带。
3. 以上都是模拟从站的结果。真 SVT10 到手后，建议抓一次真实报文复核。

## 4 下发读写（原文 p.13–15 §3.1.2、p.19 图 16）

云端向网关的订阅主题发：

```json
{
  "rw_prot": {
    "Ver": "1.0.1",
    "dir": "down",
    "id": "<任意，回复原样带回>",
    "r_data": [ { "name": "<变量名>" } ],
    "w_data": [ { "name": "<变量名>", "value": "<值>" } ]
  }
}
```

- 回复为 `"dir": "rsp"`，`id` 原样带回，`r_data` 与 `w_data` 每项都带 `err`。原文：「需要先执行写，再进行读」。
- 格式错误时，网关只回 `{"rw_prot":{"Ver":"1.0.1","dir":"rsp","err":"1"}}`。`r_data` 或 `w_data` 只有一边出错时，丢弃出错的那边，另一边照常回（原文 p.15 列了六条规则）。
- **写入值不按倍率反算**：原文图 16 中，点 `2` 的倍率为 10，下发 `"value":"92"` 后，从机寄存器里就是 92，回读的 `r_data` 为 `"920"`。
- SVT10 可写的只有 0x0006 地址、0x0007 波特率，现场运行中**不宜下发写**。下发读可用于不等下一轮轮询、立即取一次数。

## 5 我方建议的 SVT10 配法（建议，非手册内容）

### 5.1 点表：每台 14 点

寄存器口径依据 `AI-116 §1`（有人官网手册 §4.3 原表）。从机地址 NN 写成两位，下表以 NN=01 为例：

| 变量名 | 寄存器 | 数据类型 | 倍率 | 上报值单位 |
| --- | --- | --- | --- | --- |
| `a01_temp` | 0x0000 | 16 位有符号 | 0.1 | ℃ |
| `a01_vel_x` / `_y` / `_z` | 0x0001 / 0x0002 / 0x0003 | 16 位无符号 | 0.1 | mm/s（有效值，惯例） |
| `a01_acc_x` / `_y` / `_z` | 0x0013 / 0x000E / 0x0009 | 16 位无符号 | 0.01 | g |
| `a01_disp_x` / `_y` / `_z` | 0x0014 / 0x000F / 0x000A | 16 位无符号 | 1 | μm（峰峰值，惯例） |
| `a01_freq_x` / `_y` / `_z` | 0x0015 / 0x0010 / 0x000B | 16 位无符号 | 1 | Hz |
| `a01_addr` | 0x0006 | 16 位无符号 | 1 | —（传感器自报的地址） |

- 功能码一律 03。按 150 点上限，每台 14 点，一台网关**最多 10 台**。
- `aNN_addr` 是校验点：它读回的值应等于前缀里的 NN。不相等，说明点表配错了；`err` 不为 `"0"`，说明这台没响应。
- 同一路 485 上，每台 SVT10 先单独改好地址（寄存器 0x0006，出厂为 1），波特率与校验要和网关一致。
- 上报方式建议一律选「**直接上报**」，保证每包都是全量。选「变化上报」时，没变的点不出现在包里。

### 5.2 网关开关

- **勾选 SN 上报**：用 `sys_sn` 识别网关。`id` 的本义是消息编号，上报时只是「默认」填 SN。
- **勾选时间上报，选数值型 UNIX 时间戳，并打开 NTP**。原文 p.45 §3.6.4 写明 NTP「默认关闭」，最多可设 4 个 NTP 服务器。本地时间字符串不带时区，不建议用。
- **自定义字段**建议放两条：`site`（安装位置编码）、`cfg_ver`（点表版本，每改一次点表就加 1，见 §7 第 1 条）。

## 6 解析要点（供贵方参考）

1. **传感器身份 = `sys_sn` + 变量名前缀里的从机地址**。它对应哪台设备、哪个测点，由贵方点表维护，报文本身不带。
2. `value` 是字符串，要转成数值；SVT10 的点已经是工程值，不要再换算。
3. `err` 不为 `"0"` 时，这个点**不可信**：读错误时 `value` 为空，写错误时 `value` 是旧值（原文表 3 注）。
4. 断点续传补发的是历史记录。**不开时间字段时，补发的数据和实时数据分不出来**，所以 §5.2 建议必开时间。
5. 一轮约 140 次请求，每次间隔 100 ms，一轮至少 14 s，在默认 30 s 周期内。某台掉线时，它的每个点都要等满 200 ms 超时，这一轮会相应拉长。

## 7 手册未写、请现场实测

1. **变量名能否沿用**。原文 p.9：「变量名称不可重复，每次更新点位配置时，变量名称不可与上次配置相同」；p.13：「每次更新时，变量名不可与上次一致，否则配置不生效」。照字面理解，每改一次点表，变量名都得全换。如果属实，`aNN_` 前缀之后还要加版本后缀（如 `a01_vel_x_2`），解析时只认前缀和物理量。
2. **UNIX 时间戳的单位与类型**：秒还是毫秒；出 JSON 数值还是字符串。原文只写「数值型」。
3. **断点续传一包多条时的结构**：原文只写「单包上传 1–50 条」，没给样例。
4. **配了多个推送主题时，轮询数据发往哪个**：原文示例只用了推送主题 1。
