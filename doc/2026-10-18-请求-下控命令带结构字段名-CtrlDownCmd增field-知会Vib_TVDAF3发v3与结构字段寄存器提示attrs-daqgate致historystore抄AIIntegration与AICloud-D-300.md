## 1 `CtrlDownCmd` 增 `field`

### 1.1 提议

```proto
message CtrlDownCmd {
	// …… 1～11 不变 ……
	// 结构值点的字段名。空 = 整点下控(与今天逐字相同)。
	// 非空 = 只写该点的这一个字段:value 的类型是**该字段**的值类型,不是点的 VT_RECORD。
	// 语义归 daqgate(同 extra),贵方原样透传、不解释、不校验。
	string				field		= 12;
}
```

- 字段号以贵方定稿为准。我方内部回环的 `CtrlDownLocalReq`（`daqinternal.proto`）同号跟进，那份我方自己改。
- **不复用 `extra`**：`extra` 已有自己的语义（IEC 的命令限定），再捎带字段名就是一个字段两种含义，执行侧要靠内容猜是哪一种。
- `CtrlDownRelayReq` 不用改：字段名在 `cmd` 里，随命令走。

### 1.2 请贵方做的

1. 中转时把 `field` **原样带到目标网关**的 `CtrlDownChannel` 流上。若贵方是逐字段重建命令，而不是整条转发，请把 12 号也拷上；否则老网关、新网关之间会静默丢字段，变成**整点下控**，那正是要避免的。
2. 值类型照旧**不校验**（`D-294 §4` 贵方原话：不校验类型、只透传）。字段下控时 `value` 是字段类型（如 `I4`），与点的 `resultValueType`（36）不一致是预期的，请勿据此拦截。
3. 给一个能力位，例如 **`ctrl-down-field`**：担保「`field` 会被原样送到目标网关」。我方发起侧没看到这一位，就不发字段下控，界面上灰掉并说明原因。
4. 审计事件里若贵方展开下控命令内容，请一并带上 `field`；只透传 `message` 的话不用改，我方执行侧会把字段名写进 `message`（形如「点=VBST1(3750) 字段=baud」）。

### 1.3 兼容

| 组合 | 结果 |
| --- | --- |
| 老网关发起 | 不带 12 号，与今天相同 |
| 新网关发起、贵方无能力位 | 我方不发字段下控 |
| 新网关发起、贵方有能力位、目标是老网关 | 老网关不认 12 号，会按**整点**处理；结构点整点下控在任何版本都被拒（「结构值点只读」），**不会误写**。我方仍会在界面上提示目标网关版本要求 |

## 2 知会：Vib_TVDAF3 v3 与结构字段 attrs

### 2.1 Vib_TVDAF3 v3（贵方不用改）

- 按手册地址顺序，在 `z_vel` 之后增三个字段（寄存器表见 `AI-116 §1.1`）：

- 何时发到实时库由我方用户定，发之前不会动贵方的库。

### 2.2 结构字段 `attrs` 新键（贵方不用改）

贵方对 `attrs` 不定义键的语义，原样存取即可。我方新增的键都带前缀，免得与 `quantity` / `axis` 等撞：

| 键 | 含义 |
| --- | --- |
| `mb.reg` | 相对段起始的寄存器偏移 |
| `mb.acc` | 寄存器原始类型（`I2` / `UI2` / `R4` …） |
| `mb.scale` | 系数 |
| `mb.bo` | 字节序 |
| `mb.writable` | `1` = 该字段可下控 |
| `ctrl.warn` | 下控前给人看的提示 |

这些只是我方「结构配置」对话框新建结构点时的**预填缺省**，点上存的寄存器映射才是权威。只写给「一个结构只对应一个型号」的结构。

### 2.3 致 AIIntegration

- 三个新字段没有 `quantity`，不属于振动输入，`AI-116 §3` 的按字段绑定规则不受影响。
- 若贵方按结构定义的**字段全集**做校验（而不是只看绑定的那几路），v3 多出三项是否有影响，请告知。
