## 0 一句话

- 我方用户 10-18 定：**字段顺序不算布局**，与 D-302 §1 的非布局部分一样，可以在最新版上原地调整，不发新版本。
- D-302 §1 里「顺序算布局，请保持」那一条**作废**，以本函为准。
- 贵方「(结构 id, 版本) 长什么样永远答得一样」这句承诺，请改为：**布局部分永远答得一样；字段顺序与非布局部分按最新设定输出**。

## 1 依据：贵方存储不看顺序

以下是我方在贵方仓里查到的（只读）：

- 列式编码按线格式拆列，**不读结构注册表**（`src/core/compress/struct_codec.h:14-18`）。列键为 `(field number << 3) | wire type`（`struct_codec.cpp:51`），其中没有字段位置。
- 每条记录的线格式字段次序另记在 shape 里，解码时照原次序重建，逐字节还原（`struct_codec.cpp:345-354`、`610-618`）。写入方次序变了，只是多一种 shape，不影响分列，也不影响还原。
- 按字段取值、展示，都是按名字找到字段号再匹配，不看位置。
- 现在把顺序算进描述，贵方注释写明的理由是「界面展示顺序」（`struct_registry.cpp:109-110`），与存储无关。

只调顺序时，字段名和类型签名都不变，字段号不变，数据进的仍是原来的列。

## 2 请求

### 2.1 布局重新划界（取代 D-302 §1 的布局一行）

| | 内容 |
| --- | --- |
| **布局**（改了仍须发新版本） | 字段的**集合**（增删）；每个字段的 `name`、`type`、`repeated`、`dtype`、`shape`、`bigEndian` |
| **可原地调整** | 字段**顺序**；以及 D-302 §1 所列非布局部分 |

判定照 D-302 §2.1：布局相同、只有顺序或非布局部分不同时，带 `allowAttrUpdate` 就原地修改最新版；不带就拒绝；不出新版本。`modifiedMs` 同样随之更新。

### 2.2 承诺改为「按最新设定顺序输出」

- **布局部分**：同一 (id, version) 永远答得一样。字段集合、名字、类型签名、字段号都不变，旧值永远解得出来。
- **字段顺序与非布局部分**：按该版本最新的设定输出。`GetStruct`、`ListStructs`、展示形态、导出的 `FileDescriptorProto`，都按最新顺序列出字段。字段号不变，按描述解码的第三方不受影响。
- 是否改过、何时改的，由 D-302 §2.4 的 `modifiedMs` 反映。

## 3 影响

- **数据**：不受影响（§1）。
- **我方**：
  - 我方编码器按描述顺序写字段。顺序原地调整后，按新顺序写出的字节次序会变，但仍是合法线格式，进的列不变。
  - 我方按 (id, version) 缓存了描述，将按 `modifiedMs` 刷新。
  - Modbus 结构点「字段顺序 = 寄存器顺序」的约定，由我方在配置侧自己处理。
- **致 AIIntegration**：贵方有没有按字段**位置**（第几个字段）取值或绑定的地方？如果有，同一版本的字段顺序今后可能变，请告知。
